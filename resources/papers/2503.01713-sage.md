## One-Sentence Memory

SAGE improves conventional vector RAG by creating semantically complete chunks, dynamically stopping chunk selection when reranker relevance drops sharply, and using LLM feedback to adjust whether the answer received too much or too little context.

## Problem

The paper attributes many RAG failures to retrieval rather than generation:

1. Fixed-length or sentence-preserving chunking can still split a complete meaning across chunks.
2. Retrieving a fixed top-k creates a trade-off:
   - small k may omit necessary evidence
   - large k may add distracting or misleading evidence

SAGE targets precise context selection for question answering.

## Method

```text
corpus
-> semantic segmentation
-> embeddings and vector index
-> broad candidate retrieval
-> reranker relevance scores
-> dynamic selection at the relevance-score drop
-> answer generation
-> LLM judges answer and context sufficiency
-> retrieve fewer or more chunks when needed
```

### 1. Semantic Segmentation

- Begins with coarse chunks containing complete sentences.
- Evaluates adjacent sentence pairs using an embedding model plus an MLP.
- Splits where adjacent sentences are judged insufficiently related.
- Goal: produce short chunks that each carry focused, complete meaning.
- Intended advantage over LLM-only segmentation: lower offline cost and higher parallelism.

### 2. Gradient-Based Chunk Selection

- Vector search first retrieves a candidate set.
- A stronger reranker assigns relevance scores.
- Candidates are sorted by score.
- Selection continues until a significant relevance-score decrease is detected.
- This replaces one fixed top-k value with a query-dependent amount of context.

The word "gradient" here refers to the change between ranked relevance scores, not end-to-end neural-network training during retrieval.

### 3. LLM Self-Feedback

The LLM evaluates:

- answer quality
- whether retrieved context is excessive
- whether retrieved context is insufficient

If the answer is below a threshold, SAGE adjusts the minimum number of selected chunks and retries. The paper limits the feedback loop to a small number of attempts.

## Claimed Results

The abstract reports:

- average QA quality improvement of 61.25% over selected baselines
- average cost-efficiency improvement of 49.41%

These are author-reported aggregate results and should not be treated as universal production gains.

The paper evaluates variants across NarrativeQA, QuALITY, QASPER, and TriviaQA using several retrievers and LLMs. Its ablations indicate that segmentation, selection, and feedback each contribute, with the complete system generally performing best.

The paper reports a comparison with RAPTOR on QuALITY using GPT-4:

- RAPTOR + GPT-4: 82.6% test accuracy, 76.2% hard-set accuracy
- SAGE + GPT-4: 90.10% test accuracy, 76.3% hard-set accuracy

This is one benchmark configuration, not evidence that SAGE universally replaces RAPTOR.

## Relationship To Other RAG Methods

### SAGE vs Baseline RAG

SAGE retains the conventional chunk, embedding, vector retrieval, reranking, and generation architecture. It improves how chunks are formed and how many are selected.

### SAGE vs RAPTOR

| SAGE | RAPTOR |
| --- | --- |
| optimizes precise local context | provides multiple abstraction levels |
| uses semantic chunks | builds a recursive summary tree |
| dynamically adjusts retrieved chunk count | retrieves detailed leaves or higher summaries |
| targets missing and noisy retrieval | targets questions requiring different resolutions |

They can be complementary, but combining them requires evaluation.

### SAGE vs GraphRAG

| SAGE | GraphRAG |
| --- | --- |
| improves semantic chunking and local retrieval precision | models entities, relationships, and communities |
| primarily operates over text chunks and vectors | operates over graph structure plus source text |
| targets missing or noisy context | targets multi-hop and whole-corpus sense-making |

The SAGE paper cites the original GraphRAG paper but does not report a direct SAGE-versus-GraphRAG experiment.

A plausible combination is:

```text
SAGE-style semantic text units
-> GraphRAG entity and relationship extraction
-> graph communities and reports
-> adaptive local evidence selection where useful
```

This combination is an architectural inference, not a result established by the paper.

## Strengths

- Treats chunking as a first-class retrieval decision.
- Replaces fixed top-k with query-dependent context size.
- Explicitly models both missing-context and noisy-context failures.
- Includes feedback about evidence sufficiency, not only answer generation.
- Addresses token cost as well as answer quality.

## Limitations And Risks

- Requires training and operating a semantic segmentation model.
- Dynamic thresholds and feedback thresholds introduce tuning work.
- LLM self-evaluation can be unreliable or self-confirming.
- Feedback adds latency and inference cost.
- Evaluation is mainly QA-oriented and may not generalize to agent actions or high-stakes workflows.
- A relevance-score cliff may not exist cleanly for every query.
- Semantically coherent chunks do not guarantee factual completeness or correct provenance.
- The framework does not provide GraphRAG-style global graph reasoning.

## Agent-First Interpretation

SAGE can be represented inside the project loop as:

```text
intent
-> retrieve broad candidates
-> decide evidence boundary
-> respond
-> critique evidence sufficiency
-> retrieve again when needed
-> trace and evaluate
```

Useful trace fields:

- segmentation method and version
- initial candidate count
- reranker scores
- selected cutoff and reason
- selected context count
- feedback judgment: sufficient, excessive, or insufficient
- retry count
- final evidence identifiers
- answer-quality and grounding evals

## Avaloka Application

Potentially useful for retrieving memories or guidance where too much context can feel invasive or confusing:

- retrieve a broad candidate set privately
- rerank against current intent and risk
- expose only evidence above an adaptive cutoff
- ask for clarification when evidence remains insufficient
- trace why each memory or document was included

Do not adopt the complete SAGE architecture before the minimal retrieval, trace, and eval loop exists. First test its individual ideas:

1. semantic chunking versus current chunking
2. adaptive cutoff versus fixed top-k
3. external evidence-sufficiency evaluation versus model self-feedback

## Evaluation Questions

- Does semantic segmentation improve retrieval recall without making chunks too large?
- Does adaptive cutoff reduce irrelevant context while preserving required evidence?
- How stable is the cutoff across reranker models and score distributions?
- Can an independent evaluator outperform self-feedback?
- What latency and token cost does each feedback retry add?
- Do improvements persist on Avaloka-specific questions and memory policies?
