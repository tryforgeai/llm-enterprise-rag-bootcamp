## 一句话结论

整周可以压成一句话：

> **结构是真实的，收割是昂贵的，工程的艺术在于判断哪些 query 值得这笔账单。**

大规模图会长出**涌现结构** —— 社区、hub、小世界 —— 而**这些结构不存在于任何一条边里**。知识图谱从「知识本身」继承了这个结构。每一种 GraphRAG 变体，都是一次把这个涌现结构收割来做检索的尝试，**而每一种变体都必须为这次收割付钱。**

Week 04 我们从「书」爬到了「图书馆」：不再只索引作者写下的字，而是开始制造派生 artifact。但图书馆仍然是一个每本书各自立在书脊之间的地方。Week 05 做的事**在种类上就不同**：

> **把语料中的实体和它们之间的关系抽出来，一本本书就溶解了。图书馆变成了城市。**

而城市是可以被研究的。它有一套数学 —— 大规模图的数学 —— 而这套数学**不是装饰**。这一天的结构本身就是论证：

```
上午   城市的数学        （完全不提检索 —— 这是故意的）
下午   语料变成城市      （triplet、type、三层结构）
晚上   系统的林荫大道    （MS GraphRAG、MemGraphRAG）
收尾   账本              （pattern、anti-pattern、sidecar）
```

上午的数学**到了下午几乎原样回来，连编号都没磨掉** —— Leiden 长在 Microsoft 的 pipeline 心脏里，度分布长在 hub suppression 里，扩散算子长在 personalized PageRank 里。这种「回归」本身就是教学法。

## 第一幕：城市的数学

第一幕全程不提检索。这是故意的 —— 而它的每一块都会在午饭后回来。

### 欧拉的那一步

图论诞生于一座城市。1736 年的柯尼斯堡，四块陆地、七座桥，欧拉给出了那个周日谜题的答案 —— **不行** —— 而他的方法是：**把制图师会保留的一切都扔掉**，距离、岛的形状、河的宽度。剩下的是四个点和七条线。

```
G = (V, E),  E ⊆ V × V
```

> **Embedding 活在几何里；图活在拓扑里。** 欧拉的这一步 —— 丢掉几何、保留连接 —— 正是 embedding 模型拒绝走的那一步。

当我们扔掉语料的散文、只保留实体和关系时，**我们就是在走欧拉这一步。** 我们会失去一些东西；我们也会看到任何「把文章读得更仔细」都看不到的东西。这笔交换就是整周的内容。

### 邻接矩阵 —— 图从此可以计算

```
A_ij = 1 若 i 与 j 之间有边，否则 0    （知识图谱里这里是权重）
```

`A` 的幂在数路径：`(A²)_ij` 是 i 到 j 的两步路径数。**今天遇到的每一个图算法 —— 社区检测、PageRank、谱分析 —— 剥掉戏服之后，都是在 `A` 或从 `A` 派生的矩阵上做线性代数。**

行和给出第一个关键统计量 —— **度（degree）**：

```
k_i = Σ_j A_ij
```

> 记住这句，下午要用：**MemGraphRAG 的检索引擎几乎字面上就是「在三层上建 A，归一化，然后把矩阵–向量乘法迭代十次」。** 邻接矩阵不是背景，**它就是那台机器。**

### 两种随机性 —— 以及为什么真实网络有 hub

| | Erdős–Rényi | 真实世界网络 |
| --- | --- | --- |
| **模型** | 对每一对顶点以概率 `p` 掷硬币 | 以**优先连接（preferential attachment）**生长 |
| **度分布** | Poisson，`P(k) = e^{-⟨k⟩}⟨k⟩^k / k!` | 幂律 / 重尾，`P(k) ~ k^{-γ}`，γ ≈ 2–3 |
| **log–log 坐标下** | 像悬崖一样掉下去 | **一条笔直的直线** |
| **Hub** | 基本不可能 —— 尾巴以阶乘速度死亡 | **是预期之中的。** hub 是「生长 + 偏好」必然制造出来的东西 |
| **可达到的 modularity** | Q ≈ 0.32（椒盐状；接近稀疏随机本身就能伪造的水平） | Q ≈ 0.85（LFR benchmark 上十四个干净的社区） |

**Barabási 真正的贡献不是那个观察，而是那个生成故事。** 新网页链接到 Wikipedia，而不是随机页面；新论文引用那篇著名论文。富者愈富 —— 社会学家叫它马太效应 —— 而富者愈富的增长**可证明地**导出幂律。

要记住两个后果，一半用在上午，一半用在下午：

1. **Hub 让网络可导航** —— 它们是短路径穿过的机场，也是小世界之所以可能的原因。
2. **Hub 让「向外扩展」变得嘈杂** —— 碰到一个 hub，你就碰到了它连着的一切，而其中大部分和你毫无关系。

> 第 2 条就是那句一行解释：为什么朴素的 neighbor-expansion GraphRAG **恰恰在图变得有趣的时候开始退化。**

*（lesson plan 坚持的一条校准：Broido & Clauset 的 "Scale-Free Networks Are Rare" —— 真实网络是重尾的，但纯净的幂律比民间传说里罕见得多。**重尾和 hub 经得起这个批评；对指数的崇拜经不起。**）*

### 小世界与弱连接

1967 年 Milgram 的信平均经过约 **六** 次转发到达。Watts 和 Strogatz 给出了优雅的解释：拿一个高度聚类的格点网络，**只随机重连极少数边**。聚类系数几乎不降；路径长度崩塌。**几座桥就足以让世界变小。** 再加上 Barabási 的 hub，你就得到了几乎每一个真实网络的架构。

现在把整幅图翻译到知识上。STEM 包含物理和计算机；机器学习包含神经网络；其中有 transformer，其中有 attention —— 每一层都是稠密的邻里。**而且这些线会交叉：** logistic regression 同时活在机器学习、医学、计量经济学和心理学里；熵属于热力学、信息论，也属于语言建模。

> **这些交叉挂牌就是弱连接** —— 知识城市的远程捷径，**是频率过滤器最想剪掉的那条省际桥梁。**（记住这句，它会变成批判 C。）

### 分形结构 —— 但是在真实世界里

这个短语的两半都承重。

- **「分形」那一半：** 社区套社区的模式不是某一层描述的产物；它会递归出现，同一套检测机制在每一层都能找到它。**正是这个递归让 Leiden 交给我们的是一个层级，而不是一个扁平划分。**
- **「真实世界」那一半：** 你不能永远放大下去。真实网络大概给你 **两、三、四层**有意义的层级，再往下「社区」就不再有意义了。**三户人家的邻里就只是三户人家。**

> **有限的缩放深度不是遗憾，它是一个设计参数。** Microsoft GraphRAG 的层级通常 2–4 层深，正是因为真实实体图就只装得下这么多层真结构。**要更多，你就是在总结噪声。**

**尺度不变性（scale-invariance）** 是一个我们在教学上早已相信的东西的数学名字 —— 子话题在话题里，话题在学科里。当你觉得一个知识图谱「应该在好几个粒度上都有涌现主题」时，**你不是在抒情。你是在断言尺度不变性，而这个断言对大规模知识图谱是经验上、可测量地成立的。**

### Modularity、Louvain，和那个要圈起来的算法

社区是一组「内部连接密度高于外部」的顶点。高于**什么**？高于**偶然**。Newman 的 modularity：

```
Q = (1/2m) Σ_ij [ A_ij − k_i k_j / 2m ] δ(c_i, c_j)
```

把方括号念出声，因为整个思想都在里面：`A_ij` 是**实际存在的那条边**；`k_i k_j / 2m` 是**在保持每个人度数不变的随机重连下，你期望存在的那条边**。modularity 把「实际 − 期望」的**盈余**在同一社区内的点对上求和。

精确最大化是 NP-hard 的，所以这个领域靠好的贪心算法运转：

| 算法 | 做什么 | 坑在哪 |
| --- | --- | --- |
| **Louvain**（2008） | 只要提升 Q 就把顶点在社区间挪动；然后把每个社区坍缩成超级顶点，在更小的图上重复 | **可能输出内部不连通的「社区」** —— 归在同一个名字下、彼此之间却没有街道的孤岛 |
| **Leiden** | 加了一个 refinement 阶段 | **保证它报告的每个社区都是良连通的**，在它构建的层级的每一层上 |

> **把这个名字圈起来。** Leiden 不是为了应付小测的算法冷知识。它字面上就是 **Microsoft GraphRAG 心脏里的那台引擎。** 上午的数学不是「像」下午的系统；**它就是**下午的系统。

*（和 Week 04 的家族相似：RAPTOR 按 embedding 邻近度聚类 chunk；modularity 按**关系盈余**聚类顶点。RAPTOR 问「谁听起来像？」；modularity 问「谁被连在一起？」两个问题互不包含 —— 所以成熟架构两个都留着。）*

### 拉普拉斯算子 —— 一个定义，和一扇故意留缝的门

```
L = D − A          （D 是度数对角矩阵）

x ᵀ L x = Σ_(i,j)∈E (x_i − x_j)²
```

**拉普拉斯算子是一个「光滑度计」：** 当相连的邻居完全一致时它为零，每一条跨越分歧的边都让它增长。任何在边上抹平差异的过程 —— 热在金属板上传导、谣言在村里扩散、**一个分数从一个顶点渗到它的邻居** —— 都由这个矩阵支配。图上的扩散方程是 `ẋ = −Lx`。

要带走两样东西：

- **一幅图像：** `L` 的特征向量是这个图的驻波；**Fiedler 向量**（第二小）是把图一分为二的最温柔方式 —— 切口落在最少、最弱的边上，**落在图自己想裂开的地方。**
- **一个预告：** 下午会有一个检索系统，把 query 的相关性倒在图的几个顶点上，让它以受控的方式扩散出去。**它要用的机械，是这个扩散的表亲：一个拴着绳子的随机游走，名叫 PageRank —— personalized。**

## 第二幕：知识之网 —— Triplet、Type 与三层结构

### 知识是一张互联的网

```
G = { T_i },   T_i = ⟨head, relationship, tail⟩
```

为什么是三元组而不是四元组？**因为终点是一个图** —— 一条边连接两个顶点，所以一个关系绑定两个东西，关系骑在边上。**这个元数不是建模上的随意选择；它是进入第一幕所有定理的入场券。**

### Fact triplet 与 schema（本体）triplet —— 晚上那篇论文全建在这个区分上

```
⟨Einstein, born-in, Germany⟩   ⇝   ⟨person, born-in, country⟩

typing function:  φ(e) = t     φ(Einstein) = person,  φ(Germany) = country
```

**Fact 是孤立而零散的；它们底下的 type 才是那层看不见的胶水。** 一个 schema 把一大族 fact 收拢到自己底下。

*（值得保留的哲学脚注：最早的系统哲学之一 —— 迦毗罗（Kapila）传下的数论派（Samkhya）—— 认为**如果一个东西不属于任何范畴，我们根本无法认出它**。认识即范畴化。二十五个世纪后，同样的直觉换上 KDD 论文的记号重新出现，就是 typing function φ。给 OO 背景的同学一个提醒：它和「类与对象」押韵，但**别往下挖** —— 这里没有继承、没有方法、没有属性。）*

**回报是对任何语料的「三层读法」：**

| 层 | 内容 | 与其他层的关系 |
| --- | --- | --- |
| **Schema** | type 与带类型的关系 —— 本体骨架 | schema **收拢** fact |
| **Fact** | 从 passage 里挖出的具体实体与具体关系 | fact **实例化** schema；fact **指回** passage |
| **Passage** | 原始文本 —— 正是 Week 1–4 一直在检索的东西 | passage **支撑（ground）** fact |

**MemGraphRAG 完全活在这张图里。请把它放在一个安全的地方。**

### 谁来抽取：专家、机器，和 Scooby-Doo 问题

LLM 之前，知识图谱由领域专家坐着手工写 triplet —— 成本随人时线性增长，所以只有政府、Google 和制药行业负担得起像样的。然后 LLM 来了：要 triplet，triplet 就倾泻而出。

但做一下对比游戏。**专家知道上下文** —— 结果是有领域边界的、蒸馏过的、经过策展的。**机器则把文本碰巧说的一切都转录下来。** 而语料什么都会说。某处页边有一条批注 —— *待 Scooby-Doo 审阅* —— 于是 `⟨document, pending-review-by, Scooby-Doo⟩` 就成了你知识图谱里的一个 fact。版权声明、模板页脚、修订痕迹的残渣：机器勤勤恳恳地把它们全部归档，就放在物理学旁边。

> **策展是在写作时施加的过滤器；抽取把过滤这个问题推给了你。**

**第三幕的整条研究谱系 —— 从 Microsoft 的频率加权边到 MemGraphRAG 的晋升阈值 —— 都是在回答那个「过去由专家的薪水回答」的噪声问题。**

### Hub 回归：通用实体问题

从大语料里抽出来的知识图谱**就是**一个真实世界网络，所以第一幕的一切原样适用。而在知识图谱里我们可以精确说出 hub 是谁：**通用实体。** *United States. Microsoft. Protein. Person.* 优先连接保证了它们的存在；**抽取噪声让它们更加膨胀。**

> 从 "USA" 往外走两跳，你检索到的是一整本百科全书。

**下午的每一个正经系统身上都带着一道形如这段话的疤** —— MemGraphRAG 用对数**hub suppression** 温和地压制它的 type 层 hub；社区检测方法则悄悄依赖 modularity 里的 `k_i k_j / 2m` 项，**而那一项正是对「期望 hub 度数」的修正。**

> **第一幕的数学不是风景，它是疤痕组织。**

## 第三幕：GraphRAG 的多重含义

「GraphRAG」这个名字被要求承载的含义，比任何名字应该承载的都多。按顺序走一遍：

### 1. 最老的含义：邻居扩展

在旁边放一个知识图谱；query 时抽出用户提到的实体，在图里找到它们，走一两跳，把邻居的词和关系拼到 query 上。为了区分，叫它 **graph-augmented RAG**。

**对合适的问题它确实有用** —— 多跳事实型 query（「收购 X 的那家公司的 CEO 是谁？」）需要的正是一座 embedding 相似度提供不了的关系桥。

**但要认清它的性质：它是局部的。** 它永远看不到图的大尺度结构，**因为两跳的散步看不见一块大陆。** 而上午那条 hub 警告在这里兑现：从任何一个有意思的实体走两跳，你大概率会穿过一个 hub —— **恰恰在图大到有趣的时候，扩展会被通用噪声淹没。**

### 2. Microsoft GraphRAG（2024）：收割涌现

*Edge 等人，"From Local to Global" —— 标题本身就是论点。*

**它的问题：** 那些答案不在任何一个 passage 里的 query 怎么办 —— 也就是文献里叫 query-focused summarization 的**全局意义建构（global sensemaking）** query？

> *「这部小说潜在的主题动机（leitmotif）是什么？」* —— 想想这个 query 的 embedding 会落在 chunk 之间的哪里。它什么有用的都捞不上来，**因为没有任何一个 chunk 写着这个主题。** 主题是涌现的；passage 是局部的。**Week 1–4 的每一种架构 —— chunk、factoid、rewrite、QA pair —— 在结构上都无法回答。**

**要永久保留的那对石蕊试纸：**

| Query | 类型 | 为什么 |
| --- | --- | --- |
| *「这部小说潜在的主题动机是什么？」* | **全局** | 答案是整体的属性 |
| *「Tom 和 Maggie 最后怎么样了？」* | **局部** | 单个 passage 就能回答：洪水带走了他们 |

**Pipeline，四个乐章：**

1. **Extract（抽取）。** LLM 逐 chunk 扫过语料，抽出实体和关系 —— 用第二幕的词汇说就是 fact triplet —— 合并成一个语料级实体图。**实体消解（entity resolution）**（"FDA" 和 "Food and Drug Administration" 是同一个顶点吗？）不光鲜但**承重**：消解得差，图就碎，**下游每一步都继承这道裂缝。**
2. **Detect（检测）。** 在实体图上跑 **Leiden** —— 就是上午圈起来的那个名字，优化的就是黑板上那个 Q。输出的正是上午承诺的层级：2–4 层有意义的层级，「分形但真实」的结构被操作化了。
3. **Summarize（总结）。** *神来之笔。* 为每个叶子社区写一段叙事性总结 —— 它包含哪些实体、它们如何关联、涌现出什么主题 —— 然后把叶子总结合并成父社区总结，沿层级向上。**每个小子社区的主题，原本是涌现而未被书写的，现在有地方安放了。** 一个社区总结就是 Week 04 意义上的派生 artifact，**只不过它的主题是语料结构的一块。**
4. **Map–reduce。** Query 时把全局问题抛给各个社区总结（**map**），再把局部答案综合（**reduce**）成一个全局回答。

**停下来看看这条 pipeline 到底制造出了什么 —— 这是整周最美的想法。** 假设语料是两千篇物理论文，Leiden 找到一个稠密社区，其实体是*熵、第二定律、卡诺循环、玻尔兹曼分布、自由能*。那个簇的社区总结实际上就是 **「这个语料会写出来的那一章热力学权威教科书」** —— 由每一篇贡献过一条边的论文共同滋养。

> **一口气说完 RAPTOR 与 GraphRAG 的差别：** 同样的饥渴（全局理解），同样的动作（聚类，然后递归总结），**不同的底料**（embedding 空间 vs. 实体图）。**RAPTOR 聚集「听起来像」的 passage；GraphRAG 聚集「相互作用」的实体。** 方法论问题 —— *「这项研究的总体方法是什么？」* —— 是 RAPTOR 的；跨文档关系问题 —— *「主要的药物–基因相互作用主题有哪些？」* —— 是 GraphRAG 的。**成熟系统两个都索引，然后做路由。**

### 3. 那张账单

> **一本书，$1,000。**

GraphRAG 论文出来时，一位实习生拿到了一本公共领域的书 ——《卡拉马佐夫兄弟》—— 和 Microsoft 的代码，他要走了 OpenAI key，说「就调几次 LLM」。第二天早上：一张接近一千美元的账单。*（也许他跑了不止一次。但数据就在那儿。）*

现在把它放大到企业语料：

- **抽取**是**每个 chunk** 一次 LLM 调用
- **社区检测**相对便宜，但不是免费
- 然后你还欠着**叶子总结、合并总结、总结的总结** —— 沿层级一路向上全是 LLM 调用
- 而当语料变化时，图和总结开始**腐烂**，计价器重新启动

> **后继系统的每一个架构选择 —— Lazy 的延迟、Light 的瘦身、Hippo 和 MemGraph 干脆拒绝做社区检测 —— 都是对这张账单的回答。**

### 4. 中间那些，在一个礼貌的高度上掠过

| 系统 | 唯一要记住的设计选择 | 小字条款 |
| --- | --- | --- |
| **LazyGraphRAG** | **延迟。** 前置只做轻量索引（名词短语抽取、粗糙的图），把昂贵的总结放到 **query 时**、只在 query 真正触及的子图上做。索引成本下降约**两个数量级**；benchmark 质量保持 | benchmark 报告的是**平均值**，而真正全局的 query —— 那种答案不靠近任何东西的 query —— 恰恰是 query 时局部化会**悄悄返回不完整答案**（而不是错误答案）的地方。**不完整比错误更难被发现** |
| **LightRAG** | **给机器瘦身。** 实体–关系图上的双层检索，为增量更新和低成本而设计 | 把它读作生态对「原始 pipeline 对很多语料来说过度建造了」的宣告 |
| **HippoRAG** | **完全不做社区检测。** 灵感来自海马索引理论：建实体图，用 query 提到的实体做种子，跑 **personalized PageRank** 让相关性流向结构上关联的实体 | *（是 hippocampus 海马体，不是 hippopotamus 河马 —— 而且名字里没有 "Graph"，尽管核心就是图。）* 这就是上午那个扩散算子被派上了用场，**也正是 MemGraphRAG 继承的东西** |

### 5. MemGraphRAG：三种病与一块共享记忆

*Wu 等人 —— 我们用一整个公开晚上精读过的那篇。*

**讲师预先亮出的判断：** *一个卓越的想法；在实现上，仍是 work in progress。* 它**诊断疾病**的能力非常非常强；核心想法很美。*（YouTube 说它「彻底干掉了传统 RAG」。YouTube 倾向于夸张。）*

**先说诊断。** 论文认为现有 GraphRAG 方法共享一个根本缺陷：**孤立的、片段级的抽取** —— 每个 chunk 单独、在黑暗中处理，对语料没有全局视野。*（初读时的意外：GraphRAG 的全部意义不就是全局视野吗？不完全是 —— 社区检测是在**事后**、基于那些孤立抽取的产物来构建主题，然后祈祷结果不错。）* 由这个根缺陷生出三种病：

| 病 | 长什么样 |
| --- | --- |
| **主题无关（thematic irrelevance）** | 热力学书里的版权声明、Scooby-Doo 批注 —— 被归档在物理学旁边，仿佛它也是物理 |
| **逻辑不一致（logical inconsistency）** | 矛盾被一起总结。经典 GraphRAG 里没有任何东西能阻止顶层总结写成*「拿破仑入侵俄国，这既是好事也是坏事」*。**矛盾冒到顶上，然后坐在那儿，一脸困惑。** |
| **结构碎裂（structural fragmentation）** | 那个关键想法从来没有完整地进入图，因为 chunking 一刀切了下去，或者它本来就散在多篇文档里。**只要你切 chunk，你就冒着「拿到半条虫的苹果」的风险** |

**解药，两个承诺：**

1. **共享记忆（shared memory）** —— 不是 RAM，而是 agent 架构意义上的工作记忆：第二幕的那三层，被放在**一个持久的全局存储里，语料处理过程中每个 agent 都读也都写。** 一句话论点：*别再孤立地抽取；给每个 agent 一个共享的全局上下文。*
2. **agent 的社会（society of agents）** —— 一个**抽取 agent**（读 chunk，一次抽出全部三层，每个 fact 都保留一条指回源 passage 的证据链）；一个**冲突检测 agent**（扫描 fact 层找矛盾）；一个**冲突消解 agent**（扫描语料找 provenance 来裁决）。

**冲突分类法 —— 三种：**

| 类型 | 例子 | 它实际上是什么 |
| --- | --- | --- |
| **粒度（granularity）** | John 生于 Berkeley vs. 生于美国 | **包含关系**，不是矛盾 |
| **时间（temporal）** | 拜登曾是总统；特朗普曾是总统 | **都为真**，带时间索引（第 46 任；第 45 与 47 任） |
| **互斥（mutually exclusive）** | 爱因斯坦生于 1879 vs. 1880 | **真矛盾** —— 只有一个能活（1879） |

*而分类法引出却没有大声问出的那个难题：当语料给出不可调和的陈述 —— Berkeley vs. Fremont —— 而没有第三个 passage 能裁决时，会发生什么？**先记着。它会作为批判 A 回来。***

**还有一个经济上的承诺：完全不做社区检测。** 把金字塔扔掉，你就继承了那个显而易见的问题 —— 你坐在一个巨大的三层图顶上抓头：query 时怎么理解它？他们的答案是 HippoRAG 预告过的那套优美的经典机械，**这也是他们的检索能在约六十毫秒内完成的原因。**

### 建图：候选、晋升，与陪审团池

抽取 agent 填充一个暂存区 —— 一桶**候选 schema**。默认什么都不会晋升到稳定池。只有当一个 schema 的经验频率跨过阈值，它才被晋升：

```
Freq(s) ≥ τ
```

> **构建阶段的核心论点，赤裸地说出来：频率决定重要性。** 反复出现的本体模式大概重要；罕见的大概是噪声。

被晋升的 schema 带着它的 fact triplet 一起进来；那些 fact 又带着它们的 passage 进来。**那些被留下的 passage 呢？** 一个不属于任何被晋升 fact 的 passage 会变成 passage 池里的孤岛 —— 一条**结构化检索永远到不了的死路**（朴素 RAG 还能看见它；图看不见）。

> 这有点像陪审团遴选 —— 只不过在司法里被送回家的是幸运的那些。**在这个图里，他们不是。**

### 那个实验：用论文自己跑论文

我们把**论文本身**当作语料 —— 十几个好段落 —— 用论文自己的 pipeline 跑了一遍。**12 个 passage → 38 条 fact triplet → 27 个不同的 schema。** 然后完全按论文规定建 schema 频率表：

| Schema | 频率 | 价值 |
| --- | ---: | --- |
| `⟨method, uses, technique⟩` | **5** | *「太阳会升起。」* 我们当中有多少工程师会因为得知「方法会使用技术」而感到振奋？ |
| `⟨process, causes, deficiency⟩` | **3** | 承载**论文全部诊断**的那个 schema —— 它的三种病。你会给它一颗星 |
| 论文的**三个 agent** —— 它标题里的机械 | **1** | 长尾里 |
| `⟨work, licensed-under, license⟩` —— **CC-BY 版权声明** | **1** | **就坐在三个 agent 旁边** |

> **频率相同；价值相反。计数器分不清一篇论文的标题和它的法律页脚 —— 它们是同一个数字。**

**走一遍这道阶梯：**

| τ | 谁活下来 |
| ---: | --- |
| **4** | **27 个 schema 里活下来 1 个** —— 那个废话 —— 它幸存的五条 fact 构成五条互不相连的「X uses Y」边：**一个碎裂的图，而它本身就是「结构碎裂」的教科书案例 —— 正是这篇论文立志要治的那种病** |
| **3** | 诊断和架构回来了 |
| **2** | PageRank 走了回来 |
| **1** | 三个 agent 和 RAG 的存在意义回来了 —— **手牵着版权声明一起回来** |

> **没有哪一级台阶能只给信号不给噪声，因为信号和噪声共享同一个频率。**

**为什么这不是小语料的假象：** STEM 知识是 **Zipf 分布**的。最有价值的东西住在长尾深处，常常在一整本教科书里只被说过一次 —— 因为任何人做的任何事都会创造一个子领域，而**领域之间的桥，按定义就是稀有的。** 上午页边的 Granovetter 弱连接。

**而你无法通过工程绕过的那部分：切除发生在建图的时刻。** 你在检索侧再聪明也没用 —— **你无法检索一个从未被允许进入图的东西。**

*用 Week 02 的 surprisal 说法：信息量是 `−log p`，恰恰集中在频率最低的地方。**因此频率过滤器是一个 surprisal 最小化器 —— 一个被优化去遗忘自己最有信息量的事实的索引。***

**公平起见要给出反证：** 论文自己的 pilot study 表明，去掉低频三元组在他们的 benchmark 数据上**略微提升了准确率**，我们这个小实验并没有推翻他们的表格。它展示的是**他们的表格无法展示的东西**：在 Zipf 型技术语料上，频率和重要性是两个不同的量。**想法非常好；他们需要一个不同的重要性代理指标。**

### 检索：三座灯火之城

没有社区，没有总结。把每个 triplet 写成纯文本（"Einstein born in Germany"）过一遍 embedding 模型，query 也 embed 成 `q`，然后：

> **你在三座城市上空夜航 —— 一座 schema 城、一座 fact 城、一座 passage 城 —— 而 query 是一根同时挥向三座城的魔杖。** 灯泡按相关性亮起。三座城；一根魔杖；一片有差别的灯火。

*（值得提前打消的一个疑虑：query「爱因斯坦在哪里出生？」和 `⟨person, born-in, country⟩` 没有一个词相同。**它不需要相同。** 语义 embedder 就是被训练成对措辞不敏感的。**你从不把 query 转成 triplet；你让 embedding 在中间相遇。**）*

**三个初始化 —— 每层一个，每个都是一个诚实的想法穿上一个方程：**

```
实体:  P_init(e) = (1/|F_e|) Σ_{f∈F_e} Sim(q, f)
```

**用均值而不是求和**，是刻意的：求和会把失控的高分交给「出现在很多 fact 里」的实体 —— **也就是 hub** —— 而均值奖励的是相关性，不是被提及的频率。*注意这个安静的哲学脚注：**这篇论文的检索侧本来就已经在怀疑「单纯的频率」了。** 留着这个想法去看批判部分。*

```
类型:  P_init(t) = (1/|S_t|) Σ_{s∈S_t} Sim(q, s) · 1/log(deg(t)+1)     ← hub suppression
```

第一幕的通用实体问题，正面迎击。像 `person` 这样的 type 度数巨大，会统治一切，**所以你温和地把它静音。** 对数让静音很轻：度数从 10 升到 100，（以 10 为底）惩罚只从 1 变成 2。**是一条牵引绳，不是嘴套。** *是度分布的重尾写下了这个方程；Barabási 是它未署名的共同作者。*

```
段落:  P_init(p) = α·Sim(q, d_p) + σ( log( Σ_{e∈E_p} IDF(e) / (|E_p|+1) ) ),   α = 0.05
```

两个转折。**第一，阻尼 α = 0.05** —— query 到 passage 的直接相似度被打了九五折扣，相对 fact 和 schema 两个世界被**刻意低估**。**第二，一个信息密度项** —— IDF 加权的实体密度，过一个 sigmoid 压扁，于是普通 passage 低位坐着，而罕见实体密集的 passage 饱和到接近 1。*（"the" 出现在每一篇文档里 —— 别激动。一个塞满了没人听说过的实体的 passage —— 高价值，这人是谁？）*

**为什么要给 passage 节流？** 因为作者在下注 —— 而他们的消融实验支持这个赌注 —— **丰富的信息住在上面两层。** Passage 是 grounding，不是主流。

> 退化情形教会你这个设计：只剩 passage 项时，整套装置**坍缩成 vanilla RAG** —— 那道坝正是让图保持是图的东西。反过来，如果一个 query 和任何 fact、任何 schema 都不共鸣，只有一个 passage 亮着，**那 α 多大都无所谓 —— 那个 passage 依然赢，系统优雅降级为朴素检索。** 这个折扣塑造竞争，但不取消资格。

### 蜂蜜与泉眼：语义能量与 Personalized PageRank

上午最后一张欠条，全额兑现。**我们不会只挑最亮的灯泡就收工。** 我的一部分意义在我的邻居那里；**图知道一些单个分数不知道的事情。**

```
W = D⁻¹ A                              ← 「分，别倒」：按权重比例沿你的边分享出去

v^(k+1) = (1−λ) W v^(k) + λ v^(0),     λ = 1/2
```

**把它当故事读，而且要读准，因为朴素的讲法会误导人。** Query 是你倒蜂蜜的地方。种子节点是**泉眼，不是一次性的倾倒**。每一轮，每个节点把自己手里的**一半**按 W 的比例流向邻居 —— **是按比例扩散，是谣言弥散，绝不是一个走路的人在找最佳路径。** 更新的另一半不是囤积 —— **是泉眼在重新冒水**，`λv⁽⁰⁾` 每一步都在种子处重新注入最初那份 query 能量。

行进中的蜂蜜每跳减半 —— `1/2, 1/4, 1/8` —— 所以它只在一到两跳的邻域上挂一层釉，然后绳子就把它拽了回去。**这就是「λ 防止语义漂移」在机械层面的意思：把蜂蜜熬稠；它只流这么远。**

**没有人真的在走这个图。你让蜂蜜沉淀下来，然后撇走最浓的那几汪 —— 这个撇取的动作就是检索。**

**在 lesson plan 的图上测得（λ = 1/2）：** 52% 的能量留在种子上，29% 到达它的邻居，16% 到第二跳 —— **两跳之内 97%。** 这就是 λ = 1/2 为什么够用：在一个有社区的小世界里，**一切相关的东西都在附近。**

**收敛性：** 这个更新是一个压缩映射，Banach 不动点定理负责记账 —— `k` 轮之后误差以 `(1−λ)^k` 收缩。λ = 1/2、十轮，`(0.5)^10 = 1/1024` —— 千分之一。**你不需要迭代很多次。你直接停下就行。**

> **为什么是 0.061 秒：** 在堆叠的三层图上做十来次稀疏矩阵–向量乘法 —— 没有社区检测，没有总结，**query 时没有 LLM 调用。** 论文 Table 2 报告每次检索 **0.061s**，对比 **HippoRAG 的 1.6s** 和 **LightRAG 的 11s**。品一下这个一举两得：**一个 λ 同时设定了局部性（蜂蜜流多远）和收敛速度（每步误差减半）。一个旋钮，两份工作 —— 而那张 $1,000 的卡拉马佐夫账单在六十毫秒里被回答了。**

*（给关心 GNN 的：这个迭代精确地就是 **APPNP** —— Predict, then Propagate —— PPR 作为传播规则，减去可学习权重。而对「λ 和 α 能不能学出来？」的诚实回答是：能；在这里它们是被选定的。）*

## 三个批判，一种病

> *「我承诺的是辩论，不是拆台。」* 这篇论文很出色 —— 想法干净，诊断真实且测量到位，机械（冲突分类法、候选到稳定的晋升、hub suppression、信息密度）确实漂亮。**公正的阅读先给予信用，再下刀。**

### 批判 A：「grounding」是一个范畴错误

回到那个悬置的问题：不可调和的冲突 —— Joe 生于 Berkeley，Joe 生于 Fremont，没有第三个 passage 可以裁决。**消解 agent 必须选一个；他们的设计总是会消解。** 这被包装得很有原则：取来 provenance passage，让证据说话。

**但 passage 不是真相 —— passage 只是更多的文本，其可靠性从未被建模。** 「Grounded」的意思是*可追溯到某段文本*，从来不是*可追溯到为真的文本*。而当 passage 不足以确定答案时，**LLM 裁判的参数化先验会把它推向一边：裁判停止阅读，开始回忆。**

> AI 做了一个它坦白说**没有权利去做**的自动化决定 —— 这种情况需要的是 **human-in-the-loop 复核**，而不是无声的裁决。

底下还压着一个**相关误差问题**：三个 agent 跑在同一个底层 LLM 上，所以验证者和生成者共享盲点 —— **「agent 的社会」是一个模型穿了三套 prompt。** 而 Wikipedia 派生的 benchmark 抓不住这一点：在困难样例上，**参数化的回退答案和 gold answer 按构造就是重合的。**

### 批判 B：矛盾应该是一等公民

> *「三年搭 RAG 系统教会我的恰恰相反：被发现的矛盾是宝石。」*

两个部门对同一季度报出不同的收入，**这不是要被平均掉的噪声 —— 这是一个发现。** 去做根因分析。

**而且论文自己的分类法给自己定了罪。** 三种冲突类型里，**有两种根本不是矛盾：**

- **时间型**的 fact 两个都为真、带时间索引 —— **消解它就是摧毁这个索引**
- **粒度型**的配对构成一个抽象层级 —— **诚实的做法是加一条包含（subsumption）边，这会丰富这个图**
- 只有**互斥型**才是真矛盾

> **所以消解 agent 在自己三种情况里的两种中丢掉了真实信息。他们造了一台地震仪，然后把它接到「从记录里抹掉地震」上。**

**修复几乎不花钱** —— 他们本来就在挂权重，本来就在跑检测：**让检测去标注** —— 一条 `conflicts-with` 边、两份 provenance、一个置信度、一个时间有效期 —— **而不是让消解去删除。**

> **别消解矛盾；晋升它。**

而且注意：**这同时溶解了批判 A**，因为如果你在构建时从不做承诺，你就根本不会去调用那个会犯错的裁判 —— 裁决被推迟到 query 时（那时有消歧上下文），或者推给人。

### 批判 C：频率不是重要性

自实验已经按构造证明了这一点，两句话足够：**罕见的跨域宝石只出现一次，不是因为它不重要，而是因为桥本来就稀有；** 频率数的是重复，它从来没有一次测量过重要性。

**但要点出论文内部的那个讽刺**，因为只有把论文整篇读完才看得见：

| 系统的一半 | 价值理论 |
| --- | --- |
| **构建侧** | **频率即信号** —— 反复出现的 schema 被晋升，罕见的被处决 |
| **检索侧** | **频率即噪声** —— hub suppression 惩罚常见的，IDF 奖励罕见的，`P_init(e)` 里「用均值不用求和」拒绝奖励重复 |

> **一个系统里两套相反的价值理论：他们的检索侧会去加权那颗被他们构建侧抹掉的宝石。**

**修复同样几乎免费：** 候选层本来就作为暂存区存在 —— **降级，别删除**；让低于阈值的 schema 以更低权重仍可检索。**抽屉是现成的；他们把它锁着。**

### 贯穿线

**三个批判，一种病。** 论文指控 GraphRAG 在孤立的局部抽取中丢弃信息 —— **然后自己把同样的罪犯了三次：** 一个被裁决出的唯一真相（矛盾被抹掉）、一个幸存的 fact（败者被抹掉）、一组高频 schema（罕见被抹掉）。

每一个都是**在构建时刻 —— 上下文最少的时刻 —— 做出的急切的、毁灭信息的承诺，而它本可以被推迟到 query 时 —— 上下文最多的时刻。**

> # 先保存，再决定（Preserve, then decide）。
>
> 留下矛盾。留下罕见。把判断推迟到拥有最相关上下文的那一刻。**一篇关于「不要丢失信息」的论文，不应该丢掉它自己找到的最有意思的信息 —— 而修复方案不是一个更好的阈值；是「在不得不扔之前什么都不扔」的谦逊。**

*（整个晚上底下的元教训：上面的一切 —— 抽取、频率表、阶梯 —— 都来自**和一个 LLM 加十几个段落坐一个下午**。论文用 benchmark 做出有说服力的论证；一个小而诚实的实验依然能找到那道结构上的接缝。**不要只读论文。去跑它** —— 而没有哪份数据比论文自己更有诗意上的贴切。）*

## 实践者的账本

> *学术界的论文很好；企业用不同的镜片读它们 —— 经济性、可行性、可扩展性。*

### Pattern：全局意义建构

GraphRAG 方法**只在一类 query 上挣得它的饭钱**，而我们现在可以精确刻画它：

> **那种答案是语料结构的属性、而不是其中任何一个 passage 的属性的 query。**

- *「这部小说潜在的主题动机是什么？」*
- *「这五百场财报电话会里主要的监管关切有哪些？」*
- *「今年的产品收入相比去年如何，我们弱在哪里？」*
- *「本季度客户写给我们的一切里，主导的主题和张力是什么？」*

**签名永远一样：一个人要回答它，必须读完全部并形成一个心智模型 —— 而那个心智模型就是带社区的实体图。** 当答案是主题性的、比较性的、分布性的或趋势性的，**社区总结（Microsoft）或能量沉淀后的子图（MemGraphRAG）是你整个架构里唯一真正包含答案的 artifact。**

**具体的 pattern：** 由 sensemaking query 驱动的战略/分析看板；周期性语料简报（「这个月文献里有什么变化？」）；调查与根因分析工作，**其中矛盾和桥 —— 弱连接 —— 恰恰是宝石**；以及永远存在的**混合回答** —— 一个组件来自图，一个来自对数仓的 Text2SQL，一个来自朴素检索。

### Anti-pattern —— 毫不留情地点名

> **这个领域的失望，大多数是路由错了的 query。**

| Anti-pattern | 为什么失败 |
| --- | --- |
| **点查询（point query）** —— *「实验 3 用的 learning rate 是多少？」*·*「终止条款的通知期是多久？」* | 单个 passage 就能回答；朴素检索在毫秒内、以不到一美分的成本就能找到。把点查询路由进社区总结，**等于用望远镜看自己的手表** —— 更慢、更贵，而且**常常更差**，因为综合机械会把那个它本来就不是为之设计的、清晰的局部事实给糊掉 |
| **小语料** | **涌现需要质量（mass）。** 在一篇三页的随笔的实体图上跑 Leiden —— 十五个实体、二十条边 —— 你得到三个小小的「社区」，它们的总结就是在转述这篇随笔，还按 LLM 价格收费。**你没法在浴缸里探测洋流。** 在几百篇文档以下，Week 1–4 的标准级联**不仅够用，而且严格更好** |
| **实时对话通道** | 完整 GraphRAG 的 map–reduce 是**每次查询数秒级**；图的新鲜度是批处理问题；**这条 pipeline 是批处理动物。** 把它螺栓在 search-as-you-type 上，是一场等着被发现的 SLA 违约。*（MemGraphRAG 的六十毫秒在这里是真正的卖点 —— 但构建成本和新鲜度负担仍在）* |
| **万物皆图（everything-graph）** | *墓碑。* 因为 demo 很震撼，就把整个语料塞进图构建流程 |

### Sidecar：高价值文档，高价值查询

> **GraphRAG，无论哪个变体，永远是一个边车 —— 它扩展摩托车；它从不取代摩托车。经济学不允许别的安排。**

它**建起来贵**（每个 chunk 一次 LLM 调用，然后是总结金字塔，然后是永远的**新鲜度税** —— 世界在变，图会悄悄腐烂），**服务起来也贵**，除非你是 Lazy（那就在 query 时付）或者 Mem（那就已经在构建时付过了）。所以你要做路由：

**高价值文档进图。** 不是 PB 级 —— 而且注意，实践中你不会有 PB 级的连续散文；PB 级的是文档、图片和扫描件。**选出那个「组织确实需要理解其全局结构」的子语料：** 合同、备案文件、研究文献集、客户之声语料。**沼泽的其余部分留在朴素索引里，完全可检索，不作测绘。**

**高价值查询走图。** 一个**路由器** —— 学了五周之后我们能造一个 —— 把每个 query 分类为**局部 vs. 全局**，以 Mill-on-the-Floss 那对石蕊试纸为信条。局部的大多数走标准级联；**全局的少数，大概百分之五到十五，被护送到边车。** 而这少数恰恰是**高管会问的那些问题 —— 定义你系统智能上限的那些。**

> **资本支出 vs. 运营支出的框架：** 完整 GraphRAG 是**资本支出**（索引时付费，查询便宜）；LazyGraphRAG 是**运营支出**（索引便宜，按查询付费）。数据库工程师用**物化视图（materialized views）**这个名字做同样的权衡已经几十年了，答案从来一样：**取决于这个视图被读多少次。预计算是一个对查询量的赌注。下注之前先知道你的查询量。**

**而且账本要对质量诚实，不只是对钱诚实。** GraphRAG **放大抽取质量**：嘈杂的图产出无意义的社区，产出无用的总结 —— **垃圾进，自信叙述的垃圾出。** **实体消解是承重的。** 而矛盾值得作为被标注的一等边保留下来，因为**在企业里，矛盾往往是这个图所能浮现出的最有价值的东西。**

## Week 05 对我们实际改变了什么

### 1. 交付物是路由器，不是图

Lab 5 是 Week 05 唯一一个「在我们需要图之前就需要它的输出」的 lab。一个局部/全局分类器即使在**零**个图形索引的情况下也有用，因为它和坐在我们 Week 04 各种表示（raw / factoid / QA pair / summary）之上的**是同一个路由决策**。**先造路由器；让它告诉我们，我们到底有没有全局 query。**

### 2.「先保存，再决定」是今天就能用的架构原则

它的适用范围超出 GraphRAG：

- **Week 04 的派生 artifact：** 我们本来就把 raw 索引和派生索引一起留着。同一个原则，已经在遵守。
- **我们的 eval harness：** EV-006 回答了一个它本该拒答的问题，置信度还是 1.0（`tasks/T026`）。**那就是在错误的时刻做出的急切承诺。** 拒答（abstention）**就是**推迟。
- **对 88 条 Xennials factoid 的任何去重：** 就是批判 C 的修复 —— **降级，别删除。** 把近重复项以更低权重保留，而不是丢掉。

### 3. Hub 比 tokenizer 更好地解释了 EV-001

EV-001 的诊断是：去停用词之后 query 只剩单个词 `xennial`；**43 条记录都含有它、词频还都差不多**，所以 BM25 没有可区分的信号，排序坍缩到文档长度归一化上。

Week 05 给了这件事一个名字。**`xennial` 是我们语料里的一个 hub** —— 每隔一条记录就会提到的通用实体。Week 04 说「细粒度索引放大了『大量近似记录』这个失效模式」。Week 05 用网络语言说了同一件事，**而且给出了这个领域已经在用的缓解手段：hub suppression（`1/log(deg+1)`）和 IDF 加权的信息密度。** 两者都便宜，都可以在我们现有索引上实现，**而且都不需要图。**

### 4. 实体消解在「变得有趣」之前就已经承重

"FDA" vs. "the FDA" 是 Lab 1 的练习，但它同时也是**图碎裂、下游每一步继承裂缝的原因。** 如果我们真的要在真实语料上建图，**实体消解是第一笔成本，不是之后的打磨。**

## 这一周产出的工程约束

1. **账单是一等设计输入。** 抽取阶段每个 chunk 一次 LLM 调用，加上总结金字塔，加上新鲜度税。**「一本书 $1,000」是任何人提议把沼泽图谱化时该被引用的那个数据点。**
2. **构建时的阈值是不可逆的。** 你在检索侧再聪明也没用 —— **你无法检索一个从未被允许进入图的东西。** 任何在构建时应用的过滤器都需要一个降级层，而不是删除。
3. **在 Zipf 型语料上，频率不是重要性的代理** —— 而企业技术语料就是 Zipf 型的。跨域的桥只出现一次，**恰恰因为桥稀有。**
4. **矛盾是发现，不是噪声。** 把它们建模成带标注的 `conflicts-with` 边，附两份 provenance、一个置信度、一个时间有效期。**在企业里，矛盾往往是图所能浮现的最有价值的东西。**
5. **跑在同一个底层 LLM 上的「agent 社会」，是一个模型穿了三套 prompt。** 相关误差意味着验证者共享生成者的盲点。**我们要做任何多 agent 验证设计，都需要真正不同的裁判，或者一个人。**
6. **涌现需要质量。** 在几百篇文档以下，Week 1–4 的级联**严格更好**，而不只是够用。我们当前的语料远在这条线之下。
7. **GraphRAG 永远是边车。** 高价值文档进，高价值查询过，其余留在朴素索引里。

4. **路由器住在哪里？** 是现有级联前面的独立分类器，还是 agent 的一项能力？Lab 5 的锦标赛表和 Week 04 未跑的 Lab 4 消融是**同一个 artifact —— 一个实验能不能同时产出两者？**
5. **如果我们真要建图，建在哪个子语料上？** 这一周的答案是「那个组织需要理解其全局结构的子语料」。**对我们来说存在这样一个吗 —— 还是我们的语料仍然只是 demo 语料？**
6. **MemGraphRAG 的 α = 0.05 passage 阻尼在我们的数据上站得住吗？** 对直接 passage 相似度打九五折，是一个关于「信息住在哪里」的强先验。我们的 187 条记录里**只有 11 条是原始 chunk，其余 176 条是派生 artifact**，全部来自一篇 Wikipedia 文章 —— 我们的「passage 层」本身就已经主要是派生物，这个先验未必能迁移过来。
7. **实体消解：买、造，还是推迟？** 它对任何图形方案都是承重的，而且即使没有图也有用。

## 这一周在整条弧线上的位置

```
Week 01 — 端到端的 RAG pipeline
Week 02 — 向量空间为什么能工作
Week 03 — 源文档如何被切开，或被保全
Week 04 — 我们到底索不索引源文本，还是索引从它制造出的 artifact

```

Week 04 问的是*我们该索引什么？*，答案是*为 query 而写的 artifact。* **Week 05 问的是一个任何 artifact 都回答不了的问题：关于这个语料为真、而关于其中任何一个 passage 都不为真的，是什么？** 答案是结构 —— 社区、hub、桥 —— 而结构必须被**挖掘、被总结或被扩散，并且被付费。**

> **大规模图会长出涌现结构 —— 社区套社区、hub、小世界 —— 而没有任何一条边包含它。知识图谱从知识本身继承这个结构。每一个 GraphRAG 都是在赌「收割这个结构值回这张账单」；好的架构师把做 sensemaking 的少数路由到图，把做点查询的多数留在朴素索引上 —— 并且在决定之前，先保存。**
