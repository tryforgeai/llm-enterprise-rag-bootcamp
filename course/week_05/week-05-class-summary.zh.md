# Week 05 — 当图书馆变成城市：网络、社区，以及 GraphRAG 的诸多含义

*课程内容总结。来源：Week 5 lesson plan（SupportVectors, Enterprise RAG）。*

**本周的一句话：** 大图会长出涌现结构 —— 社区、hub、小世界 —— 这些不存在于任何单条边里。每一种 GraphRAG 都是在为检索收割这个结构，而每一种都得为收割付钱。*结构是真的，收割是贵的，工程的艺术在于判断哪些 query 值这笔账单。*

Week 4 我们从"书"爬到了"图书馆"。Week 5 再往前一步：把语料里的实体和关系抽出来，一本本书就溶解成一张网 —— 有大道和小巷，稠密街区和冷清郊区，人人路过的地标。图书馆变成了城市，而城市可以被研究。

## Act I —— 城市的数学

整个上午不提检索。这是故意的：下午每个系统里都能找到这些东西，连序列号都没磨掉。

**Euler 的动作（Königsberg, 1736）。** 扔掉距离和形状，只留连接：`G = (V, E)`。贯穿全天的对照：**embedding 活在几何里，graph 活在拓扑里**，各自能看到对方看不到的。

**邻接矩阵与度。** 有边则 `A_ij = 1`（知识图谱里是权重）。`(A²)_ij` 数两步路径。行和即度 `k_i = Σ_j A_ij`，高度数就是 hub。当天所有算法都是 `A` 上的线性代数换了身衣服。

**两种随机性。** Erdős–Rényi 给出 Poisson 度分布：人人中产，没有 hub，尾巴以阶乘速度死掉。Barabási–Albert 测量真实网络，发现的是幂律 `P(k) ~ k^(-γ)`，γ ≈ 2–3 —— log–log 上是直线，而 Poisson 在那里像悬崖一样掉下去。生成故事是**优先连接（preferential attachment）**：网络在生长，新来的优先连向已经连得好的。**hub 不是异常，而是"生长 + 偏好"必然制造的产物。** 两个推论：hub 让网络**可导航**（短路径经过它们），也让网络**在扩展时充满噪声**（碰到 hub 就等于碰到它连接的一切）。

**小世界。** Milgram 的信平均转 6 次就到。Watts–Strogatz：把高聚类格子随机重连几条边，路径长度骤降而聚类几乎不变。知识也是这个形状 —— 学科套主题套子主题，而罕见的跨域边就是 Granovetter 的**弱连接（weak ties）**。**新信息正是从这些罕见的桥上过来的** —— 记住，它会以 Critique C 回来。

**"fractal，但是在真实世界里"。** 两半都承重。*fractal*：社区套社区在每个尺度重现，层级才可能存在。*真实世界*：你大概只有 **2–4 个有意义的层级**，再往下"社区"就是三户人家。所以 Microsoft GraphRAG 的层级是 2–4 层 —— 再多就是在总结噪声。

**Modularity / Louvain / Leiden。** 社区是内部密度高于**随机预期**的一组顶点：

```
Q = (1/2m) Σ_ij [ A_ij − (k_i k_j / 2m) ] δ(c_i, c_j)
```

`A_ij` 是实际存在的边，`k_i k_j / 2m` 是保度随机重连时你**期望**看到的边；modularity 加总这个盈余。精确最大化 NP-hard。**Louvain** 移动顶点提升 `Q`、再坍缩社区重复 —— 快，但可能输出**内部不连通**的"社区"。**Leiden** 用 refinement 阶段精确修掉它。把名字圈起来：**Leiden 就是 Microsoft GraphRAG 心脏里的引擎**。

**Laplacian。** `L = D − A`，且 `xᵀLx = Σ_(i,j)∈E (x_i − x_j)²` —— 所有边上分歧的平方和。它是**平滑度计**，`ẋ = −Lx` 就是图上的扩散。这扇门故意留缝：下午的检索引擎是这个扩散的近亲。

## Act II —— 知识之网：三元组、类型、三层

**三元组。** `T = ⟨head, relationship, tail⟩`。为什么不是四元组？因为终点是一张图，一条边只连两个顶点 —— 这个 arity 是进入 Act I 全部定理的门票。

**fact vs. schema（ontological）triplet** —— 当晚论文整个建立其上的区分：

```
⟨Einstein, born-in, Germany⟩  ⇝  ⟨person, born-in, country⟩
```

由**类型函数** `φ(e) = t` 刻画。事实是孤立零散的，底下的类型才是看不见的胶水。

**语料的三层读法：**

| 层 | 内容 |
|---|---|
| **Schemas** | 类型与类型化关系 —— 本体骨架 |
| **Facts** | 具体实体与它们具体的关系 |
| **Passages** | 原始 chunk —— Week 1–4 一直在其上检索 |

passage 为 fact 提供 grounding；fact 实例化 schema；schema 归拢 fact；fact 又指回 passage。

**谁来抽取 —— Scooby-Doo 问题。** 前 LLM 时代靠领域专家手工造三元组：经过策展、受领域约束，代价以人年计。LLM 让抽取变便宜，也变吵了 —— 机器如实转录一切，包括页边那句"待 Scooby-Doo 审阅"，于是它成了你图里的一个事实，紧挨着物理学。**策展是在写作时施加的过滤器；抽取把过滤问题推给了你。**

**hub 回来了：通用实体问题。** 在知识图谱里 hub 是谁很明确 —— *United States、Microsoft、Protein、Person*。优先连接保证它们存在，抽取噪声把它们吹得更大。从 "USA" 走两跳，你检索到的是一部百科全书。

## Act III —— GraphRAG 的诸多含义

### 1. 最老的含义：邻居扩展

旁边放一张知识图谱，query 时找到实体、走一两跳、把邻居拼回去。对**多跳事实型 query**（"收购 X 的公司的 CEO 是谁？"）真有用。但它是**局部的** —— 永远看不到社区和主题，而且恰恰在图变得有意思时失效：走两跳大概率经过 hub，而 hub 的邻域就是一切。

### 2. Microsoft GraphRAG（2024）—— "From Local to Global"

问题是：答案不在任何 passage 里的 query 怎么办？*"这部小说底层的 leitmotif 是什么？"* 主题是涌现的，passage 是局部的 —— Week 1–4 的每种架构在**结构上**就回答不了。

1. **Extract** —— LLM 逐 chunk 扫过，合并成一张语料级实体图。实体消歧（"FDA" vs. "Food and Drug Administration"）不光鲜但承重：消歧做不好，下游每一步都继承这道裂缝。
2. **Detect** —— 在实体图上跑 Leiden，产出 2–4 层层级。
3. **Summarize** —— 每个叶子社区写一段叙事摘要，再逐层向上合并。神来之笔：**社区摘要是一种派生产物，而它的主题是"语料结构的一块"**。给它 2000 篇物理论文，热力学社区的摘要就是"这个语料会写出来的那一章权威教科书"。
4. **Map–reduce（query 时）** —— 问每个社区摘要，再综合成一个全局回答。

**RAPTOR vs. GraphRAG：** 同样的饥饿（全局意义），同样的动作（聚类后递归总结），不同的底料 —— RAPTOR 聚**听起来像**的 passage，GraphRAG 聚**互相作用**的实体。

**账单。** 一本公共领域的书跑一遍 Microsoft 的代码 ≈ **$1,000**。抽取是每 chunk 一次 LLM 调用，然后叶子摘要、合并摘要、摘要的摘要；语料一变全部腐烂，计价器重启。**后面每个系统都是对这张账单的回答。**

### 3. 中间那些，掠过

- **LazyGraphRAG** —— Microsoft 自己的二次思考。招数是**延迟**：前置只做轻量索引，昂贵的总结放到 query 时、只在触及的子图上做。索引成本降约两个数量级。小字：benchmark 报的是平均值，而**真正全局的 query** 恰恰是"query 时局部化"会悄悄返回**不完整**（而非错误）答案的地方 —— 更难抓。
- **LightRAG** —— 实体–关系图上的双层检索，为增量更新和低成本设计。等于生态在宣告：对很多语料，原版 pipeline 是过度设计。
- **HippoRAG** —— 海马索引理论。建实体图、不建社区金字塔；query 时把实体作为种子跑 **personalized PageRank**。上午那个扩散算子被拉来干活了。

### 4. MemGraphRAG —— 三种病和一块共享记忆

**诊断。** 一个根本缺陷：**孤立的、片段级的抽取** —— 每个 chunk 摸黑单独处理，没有全局视野。（社区发现是**事后**从孤立抽取的产物里造主题，然后祈祷。）由此三病：**主题无关**（版权声明被归档在物理学旁边）、**逻辑不一致**（矛盾冒到顶层摘要里坐着，一脸困惑）、**结构碎裂**（关键想法从未完整进入图）。

**解药，两个承诺。** **共享记忆** —— 三层放在一个持久全局存储里，处理期间每个 agent 都读也都写；以及 **agent 社会**：抽取 agent（一次抽三层，每个 fact 保留指回源 passage 的 evidence link）、冲突检测 agent、冲突消解 agent。**冲突分类法**：*粒度型*（Berkeley vs. 美国 —— 是包含）、*时间型*（都为真，带时间索引）、*互斥型*（只能活一个）。

**构图。** schema 落进暂存区，只有 `Freq(s) ≥ τ` 才晋升到稳定池。核心论点直白地说：**频率决定重要性。** 晋升的 schema 带着 fact，fact 带着 passage；其余一律放走。

**自我实验（把论文跑在论文自己身上）。** 十二段 passage → **38 条 fact triplet、27 个不同 schema**。频率 5 的冠军是 `⟨method, uses, technique⟩` —— "太阳从东边升起"级别的废话。频率 3：`⟨process, causes, deficiency⟩`，承载论文整个诊断。频率 1：论文的三个 agent —— 它标题里的核心机制 —— **恰好挨着** `⟨work, licensed-under, license⟩`，也就是 CC-BY 版权声明。**频率完全相同，价值截然相反。**

走一遍楼梯：τ=4 只剩一条 schema、五条互不相连的边 —— 一张碎图，本身就是**结构碎裂**的教科书案例，而那正是论文要治的病；τ=3 诊断回来；τ=2 PageRank 回来；唯一能让三个 agent 重新进场的是 τ=1，它同时手拉手把版权声明放了进来。**没有任何一级台阶能只要信号不要噪声，因为信号和噪声的频率一样。** 这不是小语料的假象：STEM 知识是 Zipf 分布的，最有价值的东西常常整本书只说一次。更要命的是 —— **截肢发生在构图时刻，你无法检索一个从未被允许进图的东西。**（公平起见：论文自己的 pilot study 显示去掉低频三元组在其 benchmark 上略微提升准确率；我们这个小实验不反驳他们的表格，它展示的是表格无法展示的东西。）

**检索：三座灯火之城。** 没有社区，没有摘要。把三元组写成纯文本嵌入，query 也嵌入，像挥魔杖一样在三座城上一挥 —— schema 城、fact 城、passage 城，灯泡按 cosine 相似度亮起：

```
实体：  P_init(e) = (1/|F_e|) Σ_{f∈F_e} Sim(q, f)
类型：  P_init(t) = (1/|S_t|) Σ_{s∈S_t} Sim(q, s) · 1/log(deg(t)+1)
段落：  P_init(p) = α·Sim(q, d_p) + σ( Σ_{e∈E_p} IDF(e) / (|E_p|+1) ),  α = 0.05
```

三个值得点名的设计：实体用**均值而非求和** —— 求和会把暴涨的分数送给 hub；类型上的 **hub suppression** —— log 阻尼器，是牵绳不是嘴套（度数 10→100，惩罚只从 1 走到 2）；段落上 **95% 的衰减**加一个经 sigmoid 压过的 **IDF 加权实体密度**项。赌注很明确：丰富的信息住在上两层，**passage 是 grounding，不是主干流**。

**蜂蜜与泉眼。** 分数接着被 personalized PageRank 重新分配。跨层链接堆成 `A`，转移矩阵 `W = D⁻¹A`（*按比例分，不要整桶倒*），初始分数堆成 `v⁽⁰⁾` —— 论文称其中装的是**语义能量** —— 然后迭代：

```
v^(k+1) = (1−λ) W v^(k) + λ v^(0),     λ = 1/2
```

query 是你浇下蜂蜜的地方，而种子节点是**泉眼，不是一次性的浇灌**：每一轮每个节点把一半按 `W` 比例流向邻居，另一半 `λv⁽⁰⁾` 是泉眼在**重新往外冒**。流动的蜂蜜每跳减半（½、¼、⅛），只够给一到两跳邻域上一层釉，然后被牵绳拽回来 —— 这就是"λ 防止语义漂移"在机械层面的意思。**没有人真的在图上走路**：让蜂蜜沉淀，撇走最浓的几摊，撇这个动作就是检索。

收敛是压缩映射（Banach），误差按 `(1−λ)^k` 缩小，十轮约 0.1%。**一个旋钮，两份工作：** λ 同时决定局部性和收敛速度。结果：十来次稀疏矩阵–向量乘法，没有社区发现，没有摘要，**query 时零 LLM 调用** —— 每次检索 **0.061 秒**，对比 HippoRAG 的 1.6 秒、LightRAG 的 11 秒。那张 $1,000 的账单，用六十毫秒回答了。（对 GNN 熟悉的人：这就是 **APPNP** —— PPR 作为传播规则，减掉可学习权重。）

### 三条批评，一种病

先肯定再下刀：诊断真实且测量扎实，机制也确实漂亮。然后：

- **A —— "grounding" 是范畴错误。** 当 passage 不足以定案时，消解 agent 仍然**总会**给答案，而 LLM 裁判的参数化先验会把它推向一边：**裁判停止阅读，开始回忆**。"Grounded" 只意味着"可追溯到某段文本"，从不是"可追溯到为真的文本"。底下压着相关误差问题：三个 agent 跑在同一个 LLM 上，"agent 社会"其实是**一个模型穿了三件 prompt 的衣服**。基于 Wikipedia 的 benchmark 抓不到 —— 困难样例上参数化回退和标准答案在构造上就重合。这类判断该走 human-in-the-loop，不是静默裁决。
- **B —— 矛盾应该是一等公民。** 两个部门报出同一季度不同营收，不是要被平均掉的噪声 —— **那是一个发现**。而论文自己的分类法把自己判了刑：时间型两边都真，粒度型该加一条 subsumption 边；只有互斥型是真矛盾。也就是说，消解 agent 在自己三种情形里的两种中丢掉了真信息。**他们造了一台地震仪，然后接线去从记录里抹掉地震。** 修复几乎免费：让**检测去标注** —— `conflicts-with` 边、两边 provenance、置信度、时间有效期 —— 而不是让消解去删除。这顺带化解了 Critique A：构图时从不 commit，就根本不会调用那个易错的裁判。
- **C —— 频率不是重要性。** 罕见的跨域宝石只出现一次，不是因为不重要，而是因为桥本来就稀有。**频率统计的是重复，从未测量过重要性。** 论文内部的反讽只有通读才看得见：构图那一半频率是**信号**（罕见的处决），检索那一半频率是**噪声**（hub suppression 惩罚常见、IDF 奖励罕见、均值而非求和拒绝奖励重复）。**它的检索端会去加权它构图端抹掉的那颗宝石。** 修复同样几乎免费：候选层作为暂存区已经存在 —— **降级，别删除**。抽屉是现成的，他们只是把它锁上了。

**贯穿线。** 每一条都是在**构图时刻 —— 上下文最少的那一刻 —— 做出的急切的、毁灭信息的承诺**，而它本可推迟到 query 时刻，上下文最多的那一刻。三个字：**先保存，再决定（preserve, then decide）。**

## 工程师的账本

**该用的模式 —— 全局意义建构。** GraphRAG 只在一类 query 上挣得回房租：**答案是语料"结构"的属性、而非任何一段 passage 的属性**的那种。"这 500 场财报会里主要的监管关切是什么？"标志永远一样：**一个人要回答它，必须读完所有东西并形成心智模型 —— 而那个心智模型就是带社区结构的实体图。** 具体场景：sensemaking query 驱动的分析型 dashboard、周期性语料简报、调查与根因分析（那里矛盾和弱连接恰恰就是宝石）。

**反模式** —— 毫不留情地点名，因为这个领域的失望大多来自路由错误的 query。

- **点查询。** 单段 passage 就能回答，普通检索毫秒级、成本不到一分钱。把它路由进社区摘要，**等于用望远镜看自己的手表** —— 更慢更贵，而且常常**更差**，因为综合机制会把清晰的局部事实糊掉。
- **小语料。** 涌现需要质量。**你无法在浴缸里探测洋流。** 文档量在几百以下时，Week 1–4 的级联严格更好。
- **实时通道。** map–reduce 是秒级/query，整条 pipeline 是批处理动物。（MemGraphRAG 的 60 毫秒有帮助，但构图成本和新鲜度负担还在。）
- **万物皆图。** 因为 demo 唬人就把整个语料推过一遍构图。

**Sidecar（边斗）。** GraphRAG **永远是边斗** —— 扩展摩托车，从不取代它。所以要路由：**高价值的"文档"进图**（合同、申报文件、研究文献集、客户之声语料；剩下的沼泽留在普通索引里，照样完全可检索，只是不建图），**高价值的"query"走图**（router 用那对石蕊试纸判 local/global —— "leitmotif 是什么？"= global，"结尾发生了什么？"= local）。占少数的 global —— 大概 **5–15%** —— 被护送进边斗，而这少数**恰恰不成比例地是高管会问的问题**，它们定义了系统的智能上限。

**capex–opex：** 完整 GraphRAG 在索引时付费、query 便宜；Lazy 索引便宜、按 query 付费。数据库工程师用 **materialized views** 这个名字做了几十年同样的权衡，答案一直是：**取决于这个视图被读多少次 —— 预计算是一场对 query 量的赌博。** 账本对质量也要诚实：**GraphRAG 会放大抽取质量** —— 垃圾进，自信叙述的垃圾出。

## Labs

1. **语料变成图。** 对 50–100 个 chunk 跑 LLM 抽取，汇总进 NetworkX。跑算法前先**看**：log–log 画度分布、亲眼找到重尾、确认 hub 就是通用实体、找出三个实体消歧失败并测量合并后 hub 榜单怎么变。
2. **社区与层级。** 在 2–3 个 resolution 层级跑 Leiden；把 modularity 与**同图的保度随机重连**对照（结构是超出随机的盈余，所以要把随机算出来）。细分到第几层就不再有意义？
3. **社区摘要与一个全局问题。** 小型 Microsoft-GraphRAG pipeline，**成本账本全程摊开，每次 LLM 调用都记下来**。同一个全局问题，map–reduce vs. 普通 top-k 并排比较 —— 中间那道缝就是 sensemaking gap，而你是付了钱的。
4. **手工熬蜂蜜。** 十几段 passage 上建三层图，实现三个初始化，迭代十次打印 `‖v⁽ᵏ⁺¹⁾ − v⁽ᵏ⁾‖`，亲眼看 Banach 的 `(0.5)^k`。扫 τ 复现那道楼梯；扫 λ 体会局部性（0.1 时蜂蜜到处乱跑，0.9 时从不离家）。
5. **Router 锦标赛。** 横跨点查询 / 中等主题 / 真正全局三个 band 的 query 集，分别跑 Week 1–4 级联、Lab 3 pipeline、Lab 4 微型版、以及带 LLM 分类器的路由混合方案。交付物是那张诚实的表：**哪套机器在哪个 band 上交得起房租** —— 而"点查询走图"那一行是**被测量出来的**，不只是被相信。

## 带走的一句话

> 大图会长出涌现结构 —— 社区套社区、hub、小世界 —— 而这些不存在于任何一条边里。知识图谱从"知识本身"继承了这个结构。每一种 GraphRAG 都是一场赌注：赌收割这个结构值回那张账单。好的架构师把少数意义建构类 query 路由到图上，把多数点查询留在普通索引上 —— 并且**在决定之前，先保存**。

上午的数学在下午原封不动地回来了：Leiden 在 Microsoft 的 pipeline 里，度分布在 hub suppression 里，Laplacian 的扩散在 personalized PageRank 里。
