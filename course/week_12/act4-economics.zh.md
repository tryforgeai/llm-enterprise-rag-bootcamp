## p.49 · THE SURVIVING STAKE：还剩什么值得省

| 幸存项 | 讲义原话 |
| --- | --- |
| **OUTPUT TOKENS** | 用了 prefix cache 的调用**仍按全价生成**，且是**输入价的 3–6 倍**；**只有语义命中能避开** |
| **THE WHOLE PIPELINE** | 一次命中跳过 embed / search / rerank / assemble；**没有任何供应商折扣碰得到这些** |
| **LATENCY** | 秒变毫秒；**在语音里，这不是折扣，这就是产品** |

### 算一笔（相对单位：输入=1，输出=5，缓存输入=0.1）

一次调用：4000 稳定前缀 + 1500 检索结果 + 300 输出

| | 计算 | 总成本 |
| --- | --- | --- |
| 什么都不做 | 5500×1 + 300×5 | **7000** |
| prefix caching | 4000×0.1 + 1500×1 + 300×5 | **3400** |
| 语义命中 | — | **≈ 0** |

剩下的 3400 里：**1500（44%）是输出 token，永远不打折**；1500 是每次都变的检索结果，**也打不了折**。

> **prefix caching 省了一半；剩下那一半，只有"根本不生成"才能省掉。**

### ⭐ 延迟那一栏改写了 $g$

$$p^* = \frac{L+\kappa}{g+L}$$

在语音场景里，$g$ 不是 \$0.01，**$g$ 是"这个产品能不能用"**。人类对话的自然停顿是 200–500ms；2 秒意味着对方以为你没听见。

$g$ 暴涨 → **$p^*$ 塌下来** → 即使承担更高风险，缓存依然划算。

**p.55 给了这个的操作方法**：*换一种赌注：延迟，而它的 **Δ 是用转化率衡量的**。*——**换记账本，不是换技术。**

## p.50–51 · THE FORMULA：盈亏平衡点，露着獠牙

$$H^* = \frac{C_{\text{ops}}}{N\,(C_{\text{full}} - C_{\text{hit}})}$$

> *缓存划算，当且仅当**命中率越过 $H^*$**。$C_{\text{full}}$ **每季度下降**；$C_{\text{hit}}$ **大致是恒定的物理**。*
> ***模型降价抬高了缓存必须越过的栏 —— 相变边界正朝着不利于你的方向迁移。***
>
> **p.51（画出来的版本）**：*在 $H^* = 1$ 那条线以上，**不存在任何命中率** —— **一整片配置区域，缓存根本不可能划算**。像读相图一样读它。*

| 符号 | 对应 p.29 |
| --- | --- |
| $C_{\text{hit}}$ | **就是 $\kappa$** |
| $C_{\text{full}} - C_{\text{hit}}$ | **就是 $g$** |

> 📌 **$p^*$ 是一次服务该不该返回；$H^*$ 是整个系统该不该存在。**一个是单笔交易，一个是整盘生意。

### 獠牙在哪

| | 为什么 |
| --- | --- |
| $C_{\text{full}}$ ↓↓ | 模型持续降价 + prefix caching 免费送 |
| $C_{\text{hit}}$ → | 向量检索和 embedding 是**你自己的算力**，**不参与模型价格战** |

$C_{\text{ops}} = \$2000/\text{月}$、$N = 100\text{万}/\text{月}$、$C_{\text{hit}} = \$0.0004$：

| 时间 | $C_{\text{full}}$ | **$H^*$** |
| --- | --- | --- |
| 今天 | \$0.0120 | **17%** ✅ |
| 降价一半 | \$0.0060 | **36%** ⚠️ |
| 再降一半 | \$0.0030 | **77%** ☠️ |

**你的命中率不会跟着翻倍。系统没变差，是及格线自己在爬。**

## p.52 · TWO VERDICTS：Build. Do not build.

> **旗舰客服机器人**：$N=50{,}000/\text{天}$，$C_{\text{full}}\approx\$0.02$，$C_{\text{hit}}\approx\$0.0004$，$C_{\text{ops}}\approx\$40$ → $H^*\approx 4\%$；实测 FAQ 命中率 **40–60%**。**Build.**
>
> **同一个机器人换 nano 档模型**：$C_{\text{full}}\approx\$0.0006$ → $H^*\approx \mathbf{400\%}$。**任何命中率都够不着。**
>
> ***「Do not build」是分析的成功，不是胆怯的失败 —— 那道教过的可行性闸门，现在带上了价签。***

$H^* > 100\%$ = **即使每个请求都命中也回不了本**。运维缓存的 \$40/天 比整个工作负载（50000 × \$0.0006 = \$30/天）还贵。

### ⭐ 只有**比值**重要

令 $r = C_{\text{full}}/C_{\text{hit}}$，$k = C_{\text{ops}}/(N\cdot C_{\text{hit}})$：

$$H^* = \frac{k}{r-1} \qquad(\text{讲义的例子里 } k = 2)$$

| $r$ | $H^*$ | 判决 |
| --- | --- | --- |
| **50 倍**（旗舰） | 4% | ✅ 建 |
| 10 倍 | 22% | ⚠️ 盯着 |
| **1.5 倍**（nano） | 400% | ☠️ 别建 |

**绝对价格无关紧要，只有「完整请求比一次命中贵多少倍」重要。**

> **缓存自己的成本地板（$C_{\text{hit}}$），就是它存在理由的天花板。**当 $C_{\text{full}} \to C_{\text{hit}}$ 时，$H^*$ **爆炸式发散**。

**自查代码：**

```python
r = C_full / C_hit
k = C_ops / (N * C_hit)
H_star = k / (r - 1)
print(f"需要命中率 > {H_star:.1%}；实测多少？")
```

## p.53 · HYGIENE：精度—频率洗白

> 左柱：**「95%」—— 命中条件下的精确率** ←「**被测量的**」
> 右柱：**~20–25% 的流量真的命中** ←「**你实际得到的**」
> 中间：***营销漏斗：一个精确率，被重新打字成了一个召回率***

| 记号 | 值 | 谁在说 |
| --- | --- | --- |
| $P(\text{对}\mid\text{命中})$ | **95%** | ✅ 报了 |
| $P(\text{命中})$ | **20–25%** | ❌ **省略了** |
| $P(\text{对且命中})$ | **≈21%** | 真正省下的 |
| $P(\text{错且命中})$ | **≈1.1%** | **每 1000 个请求 11 个错答案** |

> **换个分母，"我出手时很准" 就变成 "我覆盖了绝大部分"。**没人说谎，但分母被换掉了。
>
> **"laundering"（洗白）**：钱没变，只是省略了来源，让它看起来能用在别的地方。

### 对 $H^*$ 的直接杀伤

```text
❌ 拿 95% 去比 H* = 4%   → "二十几倍余量，闭眼建"
✅ 拿 P(命中) = 22.5% 去比 → "五倍余量，没那么宽裕"
```

**只有真正命中的请求才省钱。命中但答错的那部分不但没省，还倒欠一笔 $L$。**

**在 $H^*$ 处于 15–25% 的项目里，用哪个数做决策，结论正好相反。**

### 诚实报表的四个数

| 指标 | 回答什么 |
| --- | --- |
| $P(\text{命中})$ | 覆盖 |
| $P(\text{对}\mid\text{命中})$ | 质量 |
| $P(\text{错且命中})$ | **危害** |
| $H^*$ | 门槛（每季度重算） |

**前两个必须成对出现**（p.26 说的 *"report the demonstrated error, weekly, **next to** the hit rate"*，"next to" 三个字就是在防这一页的病）。

> 我们笔记里那句「只报 hit rate 不报 false hit rate = 只报收入不报亏损」，**这一页是它的镜像**：报了 precision，藏了 hit rate。**两种藏法，同一个病。**

## p.54–55 · Quiz 5：拯救缓存 —— 一个都不是

> nano 档判决 $H^*\approx 400\%$。团队不肯放弃。哪个动作能救？
> **(a)** 缓存容量翻倍　**(b)** 微调更好的匹配器提高命中率　**(c)** 降低 τ 把更多查找转成命中

**答案：**

> *$H^*$ 里**没有任何一个选项对应的旋钮**：(a) **容量根本没出现在公式里**；(b) 提高了命中率，**但没有命中率能超过 100%，而栏在 400%**；(c) 提高了命中率**和错误率**——你更频繁地付出 $L$，去追一道够不着的栏。*
>
> ***陷阱，又一次 —— 以及随之而来的教训：当栏本身就够不着时，每一个旋钮都是错的旋钮。唯一诚实的动作是「别建」，或者换一种赌注：延迟，而它的 Δ 是用转化率衡量的。***

| 选项 | 对实际 $H$ | **对 $H^*$** |
| --- | --- | --- |
| (a) 容量翻倍 | 略升 | **$C_{\text{ops}}$ ↑ → $H^*$ 更高** ⬆️ 倒扣 |
| (b) 微调匹配器 | 升，上限 100% | 微调要钱 + 更强的匹配器更慢更贵（$C_{\text{hit}}$ ↑）→ **$H^*$ 更高** ⬆️ 双重倒扣 |
| (c) 降 τ | 升 | **完全不碰 $H^*$**，且多了 $(1-p)L$ |

**(c) 最阴险**：hit rate 数字变好看了，但把"正确的未命中"换成了"错误的命中"——**报表变漂亮，用户拿到错答案**，正好是上一页洗白的活体标本。

> **命中率是分子，$H^*$ 是门槛。当门槛高过 100%，再怎么优化分子都是在错的方程里使劲。**

**和 Quiz 2 同一个套路**：三个选项，正确答案是"一个都不选"。Quiz 2 的病是"用一个参数解两条条目的矛盾"；Quiz 5 的病是"**用分子的努力去解分母的问题**"。

## p.56 · THE MAP OF STAKES：四份判决，一张落位图

```text
   geometry                          decision theory
   makes it POSSIBLE  ↘           ↙  makes it HONEST
                    ┌──────────────┐
                    │   the bet：   │
                    │  过去会重演    │
                    └──────────────┘
   the adversary     ↗            ↖   economics
   makes it DANGEROUS              decide if it is WORTH PLACING

   而在最高赌注处 —— actions、schemas、states ——
   成熟的动作是：**停止赌博，回到证明**
```

> *建；不建；先验证；**或者停止赌博、回到证明** —— **你坐在这张图上的哪个位置，那就是你的架构。***

（这张图和 Week 11 笔记里抄的 Rhyme Ledger 一字不差地对上了。罗马数字 II–II′/III/VI/VII 指的是专著 *CacheCraft* 的章节。）

### ⭐ 第四份判决：停止赌博，回到证明

**这是全篇最漂亮的闭环 —— 接回 p.5 的血统线：**

```text
1996  谓词包含 = 定理，可证明     ← proving
2023  余弦 + τ = 赌注，不可证明   ← betting
                  ↓
2026  在最高赌注处：回到 proving
```

**为什么 actions / schemas / states 能回到证明？因为它们都是结构化的，不是自然语言：**

| 对象 | 为什么能证明 |
| --- | --- |
| **schemas**（SQL、结构化查询） | **谓词包含还活着** —— 1996 那条定理对 SQL 依然成立 |
| **actions**（agent 工具调用） | 参数可规范化、精确比对，等价性**可判定**（见 [`act3-machine.zh.md`](act3-machine.zh.md) 的 W5H2） |
| **states**（状态） | 要么精确匹配，要么重算 —— **状态从来不该靠相似度复用** |

> **只有自然语言才被迫用赌注。其他东西不必陪着一起赌。**
>
> **工程原则：与其在一个不可证的表示上提高赌博水平，不如换一个可证的表示。**

### `where you sit on this map IS your architecture`

那个斜体的 **is** —— **不是"决定"你的架构，是"就是"。**你不需要先画架构图，回答完这几个问题，架构就已经确定了：
