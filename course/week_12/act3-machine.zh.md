## p.33 · 匹配器要专才，不要通才

> *缓存匹配是**改写检测**（paraphrase detection），**不是主题相似**——**「取消我的卡」vs「取消我的航班」是一场 0.9 余弦的灾难**。所以：一个**小编码器**（ModernBERT 量级），用**课程学习**、**解耦损失**、**难负例挖掘**做微调。*
>
> *微调课的三件套回来了：**先易后难的样本对**、**把拉近和推开分开**、**喂给编码器那些它差点信了的近似负例**。*

### 关键区分

| | 主题相似 | **改写检测** |
| --- | --- | --- |
| 「取消我的卡」vs「取消我的航班」 | 很相似（都是取消服务） | **完全不同**（答案毫无交集） |
| 通用 embedding 给的分 | **0.9** ☠️ | 应该 0.4 |

**通用编码器是为"检索相关文档"训练的，不是为"判断两个问题是否同一个"训练的。**这两个任务的目标函数不一样，用错了就是 0.9 余弦的灾难。

> 呼应 [`act1-geometry.zh.md`](act1-geometry.zh.md) 的 p.15：**领域微调 = 城市化 = 让 $d'$ 变大**。这一页说的是**微调什么模型**（小的、专用的）和**怎么微调**（课程学习 + 解耦损失 + hard negatives）。

**"小编码器"也是经济学**：$C_{\text{hit}}$ 里的 embedding 调用越便宜，$H^*$ 越低（见 [`act4-economics.zh.md`](act4-economics.zh.md)）。

## p.34 · The near-miss mine（近失矿脉）—— 第二份薪水

> *阈值**正下方**那条带，恰好富集了**你的编码器会搞混的那些配对**——把它们记录下来、聚类，它们就成了**下一轮微调的难负例**、**新兴话题的告警**、以及**技能候选**。*
>
> ***缓存不只是一个省钱工具；它是一台对准你自己编码器的仪器。挖那条带——那是你能拿到的最便宜的训练数据。***

### 为什么那条带这么值钱

```text
        ▲ 相似度
  1.00  │  ██ 明确该命中（学不到东西）
  0.92  ├── τ ───────────────────────
        │  ▓▓ ← 近失带：编码器最纠结的地方 ⭐
  0.80  ├────────────────────────────
        │  ░░ 明确不该命中（学不到东西）
  0.00  ▼
```

**难负例挖掘最贵的部分是"找到难的样本"，而缓存日志天天在免费生产它们。**

三种用途：

| 用途 | 怎么用 |
| --- | --- |
| **难负例** | 直接喂给下一轮微调 → $d'$ 上升 |
| **新兴话题告警** | 近失带突然聚集出一个新簇 = 用户开始问一类新问题 |
| **技能候选** | 反复出现的近失形状 = 值得固化成一个 skill |

> **视角倒转**：缓存不只是流水线上的一个器官，**它还是一个观测仪器**——观测的对象是你自己的 embedding 空间。

## p.35 · FRESHNESS · The evidence gauntlet（证据夹道）⭐

> ***TTL 只是猜测；世界不会来征求它的意见。**GroundedCache 拿**证据**来检验这次命中：**相似度、证据重叠、chunk 版本一致性、词面支持**——**在命中时刻串行过闸**，TTL 被降级为**兜底**。*

**"gauntlet"** 是"夹道受刑"——要连过四道闸，全过才放行：

| 闸 | 检查什么 | 抓什么 |
| --- | --- | --- |
| ① **similarity** | 意思像不像 | 问的不是同一件事 |
| ② **evidence overlap** | 当初用的那些 chunk，**现在检索还能捞到吗** | 语料结构变了 |
| ③ **chunk-version identity** | 那些 chunk 的**版本号变了没有** | 文档被改了 |
| ④ **lexical support** | 答案里的关键词，在**当前证据**里还找得到吗 | 答案内容已经失去依据 |

### ⭐ 核心倒转：TTL 从主角变成兜底

| | 旧范式（我原来记的） | **新范式** |
| --- | --- | --- |
| 主要机制 | **TTL 猜一个时间** | **命中时刻实地核对证据** |
| TTL 的角色 | 唯一防线 | **兜底**（万一闸门都没抓住） |
| 判断依据 | 时间 | **世界的当前状态** |

> **"TTLs guess; the world doesn't consult them."**（TTL 在猜；而世界不会来问它。）
>
> 一份文档可能三个月不变（TTL 7 天 = 白白丢掉 12 次命中），也可能十分钟前刚改（TTL 7 天 = 端了 7 天错答案）。**时间和正确性之间根本没有可靠关系。**

## p.36 · INVALIDATION · The version pin（版本钉死）

> *在**一套几何**下铸造的条目，**必须随那套几何一起死**：**embedder 版本和索引版本要写进条目 schema**；**不匹配 = 无条件 miss**；迁移意味着**重新 embedding，而不是心存侥幸**。*
>
> ***静默升级 embedder，会以「看起来像数据漂移」的方式腐蚀整个邻域。钉住版本——失效必须绑定索引版本，没有例外。***

### 为什么这条特别阴险

```text
embedder 从 v1 静默升级到 v2
   ↓
旧条目的向量还是 v1 空间的，新 query 的向量是 v2 空间的
   ↓
两个空间的余弦值**看起来仍然正常**（都是 0.8~0.95）
   ↓
但它们衡量的根本不是同一件事
   ↓
表现：命中率缓慢下滑 + 错答案缓慢上升
   ↓
诊断：「模型好像变笨了」「数据漂移了吧」  ← **归因完全错误**
```

**它不会崩溃，它会缓慢腐烂——这比崩溃难查十倍。**

**处方（可以直接抄进 schema）：**

```python
CacheEntry = {
    "embedding":      vec,
    "embedder_version": "bge-large-zh-v1.5",   # ← 必须
    "index_version":    "hnsw-2026-08-01",      # ← 必须
    ...
}
# 查找时：版本不匹配 → 无条件 miss，不做任何"兼容性"尝试
# 迁移 = 全量重新 embedding，不存在"渐进兼容"
```

> 这条把「**τ 不可移植**」推到了极致：**不只是阈值不能跨模型搬，缓存条目本身都不能跨模型版本存活。**

## p.37–38 · AGENTS

### p.37 规范化键（Canonical keys）

> ***Agent 的查询在「形状」上重复，而不是在「措辞」上重复。**先规范化再做 key —— **W5H2 框架**：what / where / who / when / why / how / how-much —— **参数被排除在 key 之外，命中后实时重新绑定**。*

```text
"查一下张三 8 月的报销记录"   ┐
"李四 7 月的报销查一下"       ├─→ 规范化 → shape: LOOKUP(报销, person=?, month=?)
"帮我看看王五 9 月报销"       ┘        参数 (张三/8月) 不进 key，命中后再绑
```

**形状可以精确匹配 → 不需要赌博 → 回到"可证明"。**（这正是 p.56 说的「在最高赌注处，回到证明」的具体做法之一。）

### p.38 缓存计划，不要缓存答案

> *Agent 的状态过期太快，答案缓存不了 —— **但结构会重复**：从成功的 episode 里**抽取计划骨架**，**实时绑定参数**，把长期赢家**晋升进技能库**。*
>
> *在 agent 这个高度上，**计划缓存是唯一安全的、与答案相邻的缓存** —— 它的毕业路径通向 SkillCraft 的晋升流水线。*

| | 缓存答案 | **缓存计划** |
| --- | --- | --- |
| 内容 | "张三 8 月报销了 3200 元" | "查报销 → 按人和月过滤 → 求和 → 格式化" |
| 过期速度 | **极快**（数据随时变） | **很慢**（流程半年不变） |
| 命中后 | 直接返回（危险） | **重新执行，只是省了规划** | 

> 📌 **对 Avaloka 直接相关**：agent memory 那一层不该缓存答案，该缓存**计划骨架**。

## p.39–40 · Quiz 3 —— 给一次服务定价

> **题**：语音客服机器人。一个**正确的即时回答**值 $g$；一个**错误的**要花 $L$ 去善后；**查找本身**花 $\kappa$。求**证明服务是合理的最小胜率 $p$**。
> **说回来**：为什么同一个缓存，**退款政策**问题和**营业时间**问题需要**不同的 $p$**？

**答**：

> *把赌注降到（营业时间那种）低代价 → **同一条定律，不同的门**。*
>
> ***说回来：服务门槛是由「后果的不对称性」设定的，不是由余弦设定的 —— 赌注移动 $p^*$，所以一个全局旋钮永远不可能同时给两个问题定价。***

$$p^* = \frac{L+\kappa}{g+L}$$

| 问题 | $L$ | $p^*$ |
| --- | --- | --- |
| 营业时间 | 低（用户再查一次） | 低 → 容易命中 |
| 退款政策 | 高（承诺错了要赔钱） | 高 → 很难命中 |

> **和 Quiz 2 是一对**：Quiz 2 证明「因为**条目**不同，全局 τ 不存在」；Quiz 3 证明「因为**赌注**不同，全局 τ 也不存在」。**两个独立的理由，同一个结论。**
