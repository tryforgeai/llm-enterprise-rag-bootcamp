## p.4 — THE WAGER：缓存是一场赌注，赌过去会重演

> **A cache is a bet that the past will repeat**
>
> 有史以来的每一个缓存——CPU 缓存、CDN、memoize——赌的都是**精确**重复。
> 语义缓存把赌注加大了：它赌的是**意义**会重演，哪怕**措辞**没有。同一个问题换了身衣服 → 直接给出存好的答案，跳过整条流水线。
>
> *"计算机科学里只有两件难事：缓存失效，和给东西命名。" —— Phil Karlton*
> *语义缓存做到了：**两件都占**。*

### 赌注加在哪

| | 赌的是什么 | 能不能验证 |
| --- | --- | --- |
| CPU / CDN / memoize | **字节完全相同** | 能——比一下就知道，非黑即白 |
| 语义缓存 | **意义相同** | **不能**——这是个判断，永远可能错 |

传统缓存的"命中"是一个**事实**；语义缓存的"命中"是一个**主张**。

> 这正是 γ/τ/p 存在的全部理由——因为不是事实而是判断，所以只能给概率，不能给真假。见 [`sigmoid-decision.zh.md`](sigmoid-decision.zh.md)。

### Phil Karlton 那句玩笑被用成了结构性论断

**为什么语义缓存两件难事都占？**

- **缓存失效**：底层文档变了，答案就过期——所有缓存共有
- **命名**：**这才是语义缓存独有的**

"命名"难在**划定同一性的边界**——决定哪些东西算同一个东西、配得上共用一个名字。而语义缓存每次判断"这两个问题是不是同一个问题"，做的**就是命名**：

```text
「怎么报销？」和「报销流程是什么？」   → 同一个东西，共用一个 key ✓
「报销流程是什么？」和「报销多久到账？」 → 两个东西，不能共用 ✗
        ↑
   这条边界画在哪里，就是命名问题
```

传统缓存把命名问题**外包**给了字符串（完全相同才算同一个，绝不出错，也帮不上忙）；语义缓存把它**收回来自己做**，于是拿到了收益，也继承了这件难事的全部难度。

> 这句俏皮话在这里不是抖机灵，是**给整门课定调**：ACT I–II 处理"命名"（同一性怎么判），ACT III 及之后处理"失效"（怎么知道答案过期了）。

**隐喻留存**：*Same question, different clothes* —— **问题是身体，措辞是衣服。缓存要认的是人，不是衣服。**危险也在这里：换了衣服可能真的是另一个人。

## p.5 — THE LINEAGE：从奇迹到专科仪器

> **From miracle to specialist instrument**

| 年份 | 事件 | 一句话 |
| --- | --- | --- |
| **1996** | 语义缓存作为一条**定理**（谓词包含） | 那时候**能证明**命中是对的 |
| **2023** | GPTCache：定理被换成**赌注**（余弦、τ） | 开始会出错了 |
| **2024** | 供应商前缀缓存浪潮；GPTCache 最后一个版本 | **省钱的部分被免费送掉了** |
| **2025** | vCache：给赌注**定价**（逐条目、预算 δ） | 承认是赌博，那就上保险 |
| **2026** | CacheAttack：**对手登场** | 有人专门来让你输 |

> *GPTCache（2023）开创了这个领域，如今已被弃置——只剩它自己的引用还活着（survived by its own citation，讣告句式的黑色幽默）。它不是死于竞争对手，**它死于一次价格变动**。ACT IV 会解释。*

### 1996：它曾经是一条定理

数据库领域的语义缓存，核心机制是**谓词包含**（predicate containment）：

```sql
缓存里存着： SELECT * FROM employees WHERE salary > 100000
新来的查询： SELECT * FROM employees WHERE salary > 150000
```

`salary > 150000` 被 `salary > 100000` **逻辑包含** → 新查询的答案**必然**是缓存结果的子集，本地筛一遍就行，**根本不用碰数据库**。

关键是「必然」二字：**这能证明，不会错。**

### 2023：定理换赌注 ← 全课的转折点

自然语言没有谓词，无法做逻辑包含。于是换成 `余弦相似度 > τ`。

| | 1996 谓词包含 | 2023 余弦 + τ |
| --- | --- | --- |
| 判据 | 逻辑蕴含 | 几何距离 |
| 会不会错 | **不会** | **会** |
| 性质 | 定理 | **赌注** |

> **bet 不是修辞，是一个技术史事实：这个领域在 2023 年主动放弃了证明。**

### 2024：价格变动杀死 GPTCache

各家 API 上线 prompt caching，把**零风险那部分收益**直接吃掉。回到命中门槛：

$$p^* = \frac{C}{G + C}$$

**降价 + prefix caching 免费拿走一大块 → G 暴跌 → 分母变小 → $p^*$ 逼近 1 → 几乎没有 query 够得着门槛。**

> **GPTCache 不是被更好的缓存打败的，是被分母打败的。**它赌的事还是对的（意义会重复），只是赢了不再值钱，输了照样很贵。
>
> 这解释了为什么经济学要单独占一幕——**语义缓存的存亡由一个外生变量决定，而那个变量不在你手里。**

### 2025 / 2026

- **vCache**：per-entry + budget δ，详见本文末尾「ACT II 前瞻」一节
- **CacheAttack**：对应 INTERLUDE，疑似与缓存计时侧信道 / 投毒有关，待课上确认

### 骨架

```text
1996  定理     可证明，但只适用于 SQL 谓词
2023  赌注     适用面变宽了，但放弃了证明
2024  贬值     赢面还在，赌金没了
2025  精算     承认是赌注，于是给它上保险
2026  对手     还有人专门来让你输
```

**「从奇迹到专科仪器」= 每一步都在收窄它的适用范围。这一页是在给整门课降预期：别把语义缓存当默认开关，它是一把有明确适应症的手术刀。**

## p.6 — THE ANATOMY：一次查找，三道门

> **One lookup, three doors**

| 环节 | 做什么 | 注解 |
| --- | --- | --- |
| **exact tier** 精确层 | 规范化 key 的哈希 | 在头部流量上省掉 embedding 调用 |
| **embed** 编码 | 小型专用编码器 | **延迟的大头**；用 P-CHR 评分 |
| **search** 检索 | 只对向量做 HNSW | 亚毫秒；FPR_ANN < 0.1% |
| **decide** 决策 | 逐条目曲线，预算 δ | **长大成人的阈值** |
| **verify** 验证 | 异步裁判 / 同步校验 | 用在损失 L 要求担保的地方 |
| **payload** 载荷 | KV 存储——回答、来源、版本 | 版本钉死；**绝不放进索引** |

> *精确哈希层第一（微秒级、免费），语义层第二（**证据，而非证明**），完整流水线最后——而且每一次生成都要**回写**。这就是 **Front Door 模式**。*

### 「三道门」= 三个出口，不是六个环节

```text
用户问题
   │
   ├─→ ① 精确哈希命中 ─────────────────→ 返回   ⏱ 微秒   💰 免费
   │        ↓ miss
   ├─→ ② 语义层命中（decide/verify 放行）→ 返回   ⏱ 几十毫秒 💰 便宜
   │        ↓ miss
   └─→ ③ 完整 RAG 流水线 ──────────────→ 返回   ⏱ 秒级   💰 贵
                                            ↓
                                        **回写缓存**
```

成本从上到下递增。设计目标是**让尽可能多的请求死在第一道门**。

### 为什么精确层必须排在语义层前面

**语义层本身是有成本的**——要做语义匹配，先得调 embedding 模型（`embed` 那行标着 *latency-dominant*，**延迟的大头就在这**）。走语义层就已经花了钱。

而企业流量是**极粗的头部 + 长尾**，头部那几十个问题用户往往**一字不差**地重复问（从 FAQ 页复制、从 Slack 粘贴）。这部分用哈希秒杀，**连 embedding 都不用调**。

### `hash of canonical key` —— 关键在 canonical

不是对原始字符串哈希，是先**规范化**再哈希：

```text
"报销流程是什么？"      ┐
"报销流程是什么"        ├─→ 规范化 → "报销流程是什么" → 同一个哈希
"  报销流程是什么？  "  ┘
```

讲义 p.62 把它列为独立模式：**Canonical Key · cache the meaning, not the wording**（缓存意义，不是措辞）。

p.37 补充：agent 流量用 **W5H2 框架**规范化（what / where / who / when / why / how / how-much），参数抽出来不参与 key，命中后再重新绑定。因为 *"agent 的查询在**形状**上重复，而不是在**措辞**上重复"*。

### `evidence, not proof` —— 全页最重要的六个字

**语义层给的是证据，不是证明。**直接呼应 p.5 的 lineage：1996 是 proof，2023 之后只是 evidence。

所以才需要后面两行：**decide** 把证据变成概率和承诺（δ），**verify** 在赌注够大时把证据**升级成担保**。

> 讲义 p.27：*"验证是「大概对」和「已送出」之间的收费站。"*

### `payload ... never in the index` —— 索引与存储必须分家

| | 向量索引（HNSW） | Payload 存储（KV） |
| --- | --- | --- |
| 存什么 | **只有向量** | 回答、来源（provenance）、版本 |
| 为什么 | 要常驻内存、要小、要快 | 可以很大，放磁盘/对象存储 |

**`provenance` 和 `versions` 是失效机制的地基**——记住这条答案当初用了哪几个文档的哪个版本，源文档一更新就能**定向失效**，而不是全清或干等 TTL。这就是 *version-pinned*。

### `every generation writes back`

第三道门跑完，结果**必须写回缓存**，否则系统自己不会成长。这也是「Front Door」的由来：**缓存不是旁路，是唯一入口**——所有流量从这道门进，所有结果从这道门出并留下痕迹。

### 两个待确认

- **P-CHR** —— 讲义正文没展开（在图里）。按上下文推测是「精度加权的缓存命中率」，即同时考虑命中率和命中正确率的复合指标
- **FPR_ANN < 0.1%** —— 要求 ANN 索引本身的误差**远小于**语义判断的误差，这样 HNSW 的近似性不会污染 δ 那个承诺

## p.7 — THE FIELD GUIDE：它不是什么

> **What it is not**
>
> 纵轴 — 复用的是什么：**计算 → 答案**
> 横轴 — 匹配方式：**精确 → 近似**

```text
复用答案 ↑
         │  （空象限）              ★ semantic cache
         │  = 那就是个数据库           完成的答案，近似匹配
         │                          ← 家族里唯一会出错的成员
         │  embedding cache
         │  文本→向量，精确 key
         │
复用计算 │  prefix caching      KV-cache reuse
         │  供应商 KV，省 ~90%   分块状态，修补过的注意力
         └────────────────────────────────────────→
         精确匹配                        近似匹配
```

> *每条边界一句话：不是 prefix caching（精确 token、供应商侧），不是检索（它只**找到**，从不**回答**），不是记忆（记忆是关于**你**的，不是关于**问题**的）。*

### 1. 语义缓存孤零零待在右上角

它同时把两个维度推到极端：**既复用最贵的东西（完整答案），又用最宽松的方式匹配（近似）**。

**风险正是从这个位置来的**——越靠右上，省得越多，也越容易错。这把"语义缓存最危险"从经验观察变成了**结构性结论**。

### 2. 空象限那句话最妙

> *"没人在 LLM 规模上提供精确匹配的**答案**——那玩意儿就是个数据库。"*

精确匹配 + 返回完整答案 = **数据库 / FAQ 表 / 查表**，不叫缓存。

**缓存之所以是缓存，是因为它接受某种程度的不精确或不完整。**一旦两头都要求完美，它就退化成另一种东西了。

（p.6 那个 exact-hash 层之所以还算缓存的一部分，是因为它是**回退链条的一环**，而不是整个系统。）

### 3. `~90% off` 直接解释了 p.5 的死因

prefix caching 便宜 **90%**，零风险，**供应商免费给**。

回到 $p^* = C/(G+C)$：**prefix caching 把 G 里最容易拿的那 90% 直接拿走了**，留给语义缓存的增量收益所剩无几，风险却一分没减。

**p.5 和 p.7 是同一个论证的两半。**

### 4. 三条边界，第三条最容易搞混

| 不是什么 | 区别在哪 |
| --- | --- |
| **不是 prefix caching** | 精确 token 匹配，而且在**供应商侧**——你控制不了，也不用你实现 |
| **不是检索（retrieval）** | *"它只**找到**，从不**回答**"*——检索返回 chunk，缓存返回**成品答案** |
| **不是记忆（memory）** | *"记忆是关于**你**的，不是关于**问题**的"* |

**第三条对 Avaloka 特别相关：**

| | 缓存 | 记忆 |
| --- | --- | --- |
| 按什么分区 | **问题** | **用户** |
| 跨用户共享 | 是（**这正是收益来源**） | **否**（共享就是事故） |
| 随时间 | 会过期 | 会累积 |
| 目的 | 别重复算 | 别忘了你是谁 |

> 搞混的后果很具体：**把 memory 当 cache 用 → 跨用户泄露个人信息；把 cache 当 memory 用 → 缓存永不失效，全是陈旧答案。**

### vCache: promise δ, not τ（p.26）

> **A threshold is a hope. A contract is a measurable promise.**
> （阈值是一个愿望。合同是一个可度量的承诺。）

把 `if 相似度 ≥ 0.92` 换成：

$$\Pr[\text{wrong serve}] \le \delta$$

**只在「答错的概率不超过 δ」时才返回缓存。**

| | τ（阈值） | δ（误差预算） |
| --- | --- | --- |
| 你说的话 | "我用 0.92 这个数" | "我保证错误率 ≤ 2%" |
| 这是什么 | 一个**旋钮位置** | 一个**结果承诺** |
| 业务方听得懂吗 | 听不懂 | 听得懂 |
| 能不能验证 | 不能 | **能** |

**三个关键设计：**

1. **per entry** —— 每条缓存条目一条自己的曲线，不是全局一个 τ
2. **exploration labels** —— 即使相似度够高也**偶尔故意走一次完整 RAG**，比对真答案，拿到"这次如果命中是对是错"的标签；攒够标签拟合出该条目的「相似度 → 出错概率」曲线（bandit 式探索-利用）
3. **demonstrated error** —— 实测错误率**每周和命中率并排上报**。δ 是 *stated*（声明），必须用 *demonstrated*（实测）来兑现

**p.30 的小测验说明了为什么必须 per-entry：**

> 缓存里有两条：
> A.「什么是 RAG？」——**正确**的改写匹配低到 0.83 都还对
> B.「最大日剂量是多少？」——**错误**的匹配能高到 **0.96**
> 请选一个全局阈值让两条都好使。

**选不出来**——A 需要 τ ≤ 0.83，B 需要 τ > 0.96，**两个区间根本不相交**。完整解答见 [`act2-decision.zh.md`](act2-decision.zh.md) p.30 一节。

**最狠的一句：**

> **δ is portable and τ never was.**（δ 可移植，τ 从来都不是。）

换 embedding 模型 → 余弦分布整体平移，**所有 τ 全部作废**，得从头再扫。但「错误率 ≤ 2%」这个承诺**跨模型依然成立**，重新学一遍曲线即可。

> 因为 **τ 是几何语言，δ 是业务语言**。几何随模型变，业务承诺不变。

### 四级阶梯（p.25）

| 级 | 做法 | 需要什么条件 |
| --- | --- | --- |
| **1** | 静态 τ，扫一遍定下来，P-CHR 上报，每周抽样打分 | FAQ 类流量——**市面上的产品都停在这一级** |
| **2** | 按流量类别分组，各组一套阈值 / TTL / 配额 | 流量类别可辨识 |
| **3** | **误差合同**：逐条目学曲线、预算 δ、探索标签 | 流量够密 + 有标注来源 |
| **4** | **验证**：近失区交异步裁判，L 残酷处同步判 | 赌注极高（L/(g+L) 接近 1） |

**选级判据：$L/(g+L)$。**

> ⚠️ **这正是我们自己推出来的 $p^* = C/(G+C)$**，只是讲义用 L（loss）、g（gain）。推法完全一致，可以直接对上号。

底下那句值得记：

> ***"产品都发在第一级，文献活在第三、第四级——这两级的落差是这份讲义里最可利用的事实。"***

翻译成人话：**市面上现成的语义缓存网关全都只做了最原始的静态阈值。做到第三级就有明显的竞争优势。**
