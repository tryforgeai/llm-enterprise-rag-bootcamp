## p.24 · TO CACHE OR NOT TO CACHE：$d'$

标题引德鲁克：***"Engineers often do efficiently what shouldn't be done at all."***
（把根本不该做的事做得很高效，是最没用的事。）

> *测度集中给的是**两个**紧致的峰，不是一个尖刺。**可缓存性**就是它们的**位移除以宽度**，即 $d'$：**一个好的编码器 E 让它最大化**，τ 坐在**山谷**里，而那片灰色的重叠**没有任何 τ 能消除**。*

$$d' = \frac{\mu_{\text{right}} - \mu_{\text{wrong}}}{\sqrt{\sigma^2_{\text{right}} + \sigma^2_{\text{wrong}}}}$$

### 这张图修正了 p.12

p.12 说随机向量集中在**一个尖峰**（余弦≈0）——那是"随便扔一个向量"。**实际检索时看到的是最近邻**，这时集中性给的是**两个峰**：

```text
密度
 │        红：答错的匹配              蓝：答对的匹配
 │           ╱▔▔╲                        ╱▔╲
 │          ╱    ╲                      ╱   ╲
 │         ╱      ╲____▁▁▁▁▁▁▁▁▁▁▁▁▁▁╱     ╲
 └─────────────────────┴────────────────────────→ 余弦
        μ_wrong≈0.76   ↑ τ 在山谷      μ_right≈0.90
                  灰色重叠 = 不可避免的误差
```

**两个峰都很窄**（集中性的功劳），**关键是隔多远**。

### 三档判决

| $d'$ | AUC | 判决 |
| --- | --- | --- |
| **≈ 0.6** | 0.66 | **不要建缓存** |
| **≈ 1.7** | 0.885 | **勉强** —— 逐条目定阈值 + 验证 |
| **≈ 3.3** | 0.990 | **建** —— 全局一个 τ 基本够用 |

（换算：$\text{AUC} = \Phi(d'/\sqrt2)$）

### ⭐ $d'$ 就是我们记的 γ

假设两堆都是方差 $\sigma^2$ 的正态分布，做对数似然比：

$$\log\frac{P(s \mid \text{right})}{P(s \mid \text{wrong})} = \frac{\Delta\mu}{\sigma^2}\left(s - \frac{\mu_{\text{right}}+\mu_{\text{wrong}}}{2}\right)$$

过 sigmoid 得后验。对照 $p = \sigma\big(\gamma(s-\tau)\big)$：

$$\gamma = \frac{\Delta\mu}{\sigma^2} \qquad\qquad \tau = \frac{\mu_{\text{right}}+\mu_{\text{wrong}}}{2}$$

**两个结论直接掉出来：**

1. **τ 就是两峰的中点** —— 这就是 **"τ sits in the valley"**。它不是玄学数字，是**两堆分布的几何中点**，初值不用瞎扫。
2. $d' = \Delta\mu/(\sigma\sqrt2)$，所以 $\gamma\sigma = \sqrt2\,d'$ —— **$d'$ 就是用 σ 做单位量出来的 γ。**

> 我们记的「γ 小说明该换模型」，讲义的说法是「$d' < 1$ 就别建缓存」——**同一句话**。但 $d'$ 是信号检测论的标准量（二战雷达起家），有现成判据表，比 γ 更好用。

### "a good E maximizes it" —— 微调该看的指标

$E$ = encoder。**一个好的编码器就是让 $d'$ 最大的编码器。**

这回答了 p.15 留的问题：评估微调不看 hit rate，**看 $d'$**。而且微调的目标函数和它天然对齐：

- **alignment ↑** → $\sigma_{\text{right}}$ 变小 → 分母小 → $d'$ ↑
- **uniformity ↑** → $\Delta\mu$ 变大 → 分子大 → $d'$ ↑

**p.15 的大都市效应，量化出来就是 $d'$ 变大。**

### "灰色重叠没有任何 τ 能消除"

- τ 往右挪 → 少犯错，但蓝色左尾也被拒 → hit rate 掉
- τ 往左挪 → 多命中，但红色右尾也放进来 → false hit 涨

> **调阈值是在重新分配错误，不是在减少错误。想减少错误只能把两个峰推开——那是编码器的活。**

### 落地

```python
mu_r, sd_r = stats(similarities_of_correct_matches)
mu_w, sd_w = stats(similarities_of_wrong_matches)
d_prime = (mu_r - mu_w) / sqrt(sd_r**2 + sd_w**2)

if d_prime < 1.0:
    raise DontBuildThis            # 建了就是"把不该做的事做得高效"
elif d_prime < 2.5:
    use_per_entry_curves(); enable_verification()      # 阶梯 3–4 级
else:
    use_global_tau(midpoint(mu_r, mu_w))               # 阶梯 1–2 级
```

## p.25 · THE LADDER：四级阶梯

| 级 | 做法 | 需要什么条件 |
| --- | --- | --- |
| **1** | 静态 τ，扫一遍定下来，P-CHR 上报，每周抽样打分 | FAQ 类流量 —— **市面产品都停在这级** |
| **2** | 按流量类别分组，各组一套阈值 / TTL / 配额 | 流量类别可辨识 |
| **3** | **误差合同**：逐条目学曲线、预算 δ、探索标签 | 流量够密 + 有标注来源 |
| **4** | **验证**：近失区异步裁判，$L$ 残酷处同步判 | $L/(g+L)$ 接近 1 |

**选级判据：$L/(g+L)$。**

> ***"产品都发在第一级，文献活在第三、第四级——这两级的落差是这份讲义里最可利用的事实。"***

**翻译成人话：市面上现成的语义缓存网关全都只做了最原始的静态阈值。做到第三级就有明显的竞争优势。**

### 两个维度合起来是一张决策表

| | **$d'$ 高**（分得开） | **$d'$ 低**（分不开） |
| --- | --- | --- |
| **$L/(g+L)$ 低**（错了没关系） | 第 1 级：全局 τ，发车 | 别建，或只缓存 embedding 层 |
| **$L/(g+L)$ 高**（错了很惨） | 第 3–4 级：逐条目 + 验证 | **别建。**再多工程也救不了 |

- **$d'$ 决定「能不能缓存」**（模型能力）
- **$L/(g+L)$ 决定「要多小心」**（业务赌注）

**德鲁克那句话针对的正是右边两格。**

## p.26 · THE CONTRACT：vCache —— promise δ, not τ

> ***A threshold is a hope. A contract is a measurable promise.***
> （阈值是一个愿望。合同是一个可度量的承诺。）

把 `if 相似度 ≥ 0.92` 换成：

$$\Pr[\text{wrong serve}] \le \delta$$

**只在「答错的概率不超过 δ」时才返回缓存。**

| | τ（阈值） | δ（误差预算） |
| --- | --- | --- |
| 你说的话 | "我用 0.92 这个数" | "我保证错误率 ≤ 2%" |
| 这是什么 | 一个**旋钮位置** | 一个**结果承诺** |
| 业务方听得懂吗 | 听不懂 | 听得懂 |
| 能不能验证 | 不能 | **能** |

三个关键设计：

1. **per entry** —— 每条缓存条目一条自己的曲线
2. **exploration labels** —— 曲线的燃料，来源见 p.27
3. **demonstrated error** —— 实测错误率**每周和命中率并排上报**。δ 是 *stated*（声明），必须用 *demonstrated*（实测）兑现

> ***δ is portable and τ never was.***
>
> 换 embedding 模型 → 余弦分布整体平移，**所有 τ 全部作废**。但「错误率 ≤ 2%」跨模型依然成立，重新学曲线即可。
>
> **因为 τ 是几何语言，δ 是业务语言。几何随模型变，业务承诺不变。**

## p.27 · ASSURANCE：验证通道

```text
query q ──→ 相似度 s（对条目 i）──→ ◇ P_i(correct|s) 过得了预算 δ 吗？
                                        │
            ┌───────────────────────────┼───────────────────────────┐
            │ confident yes             │ uncertain                 │ below band
            ↓                           ↓                           ↓
       ┌─────────┐       ┌──────────────────────┐    ┌────────────────────────┐
       │ serve rᵢ│       │ explore：            │    │ near-miss band         │
       │ 直接返回 │       │ 返回缓存 **并且**     │    │ → 异步裁判              │
       └─────────┘       │ 跑完整流水线；比对    │    │ （被祝福的配对晋升）     │
                         └──────────┬───────────┘    └───────────┬────────────┘
                                    │ label                      │
                                    ↓                            ↓
                         ┌────────────────────────────────────────┐
                         │          更新条目 i 的曲线               │
                         └──────────────────┬─────────────────────┘
                                            └──→ 回到决策菱形
```

> *相似度是**证据**；**裁判**把证据转换成**担保**——对近失区**异步**地祝福，在"错不起"的地方**同步**地判。**验证是「大概对」和「已送出」之间的收费站。***

### 从二元变三元

普通缓存只有命中/未命中两个出口。这里有三个：

| 分支 | 条件 | 做什么 | 用户体验 | 你付出 |
| --- | --- | --- | --- | --- |
| **serve** | 自信通过 δ | 直接返回缓存 | 快 | ≈0 |
| **explore** | 不确定 | **返回缓存 + 同时跑完整流水线，比对** | 快 | **全价**（换一个标签） |
| **near-miss** | 低于服务带但不远 | 走正常流程；**异步让裁判评这一对** | 正常 | 裁判成本 |

**"不确定"不再是失败，而是一个可以主动利用的状态。**

### `explore: serve *and* invoke` —— 标签的来源

p.26 说曲线"learned per entry from exploration labels"，标签就是这么来的：

```text
不确定区的一个 query：
  ① 立刻把缓存答案返回给用户    ← 用户不用等
  ② 同时在后台跑完整 RAG        ← 你自己掏钱
  ③ 比对两个答案
  ④ 得到一条标签：「s=0.88 这次是对/错」
  ⑤ 更新条目 i 的曲线
```

**标准的 explore / exploit：花钱买关于自己的知识。**

### `near-miss band → async judge (blessed pairs promoted)` —— 缓存的成长通道

```text
s=0.83，低于服务带 → 不敢返回，走完整流水线（用户拿到正确答案）
      ↓ 异步，不影响延迟
  裁判审视这一对：「怎么报销」vs「报销流程是什么」
      ↓
  判定确实等价 → **祝福（bless）** → 晋升 → 更新曲线
      ↓
  **下次 0.83 就敢返回了**
```

> **没有这一支，缓存的服务带永远只会收紧不会放宽**——因为你只在命中时才拿到反馈，永远学不到"其实我本可以命中"。**near-miss band 是缓存唯一的成长通道。**

### 同步 vs 异步

| 模式 | 什么时候用 | 代价 |
| --- | --- | --- |
| **异步验证** | 一般情况 | 零延迟；但错答案已送出，只能事后修正曲线 |
| **同步验证** | $L/(g+L)$ 接近 1（药品剂量那类） | **加延迟**；但错的东西出不了门 |

**"收费站"的意思是：你必须付点什么（延迟或算力）才能通过。付不起就只能降级到低一级阶梯。**

## p.28 · THE PHYSICS CROSSOVER, AGAIN：调速器，不是闸门

> *麦克斯韦，1868：**离心式调速器**靠**反馈**维持转速，而不是靠一个固定阀门。误差合同就是同一台机器——**探索负责测量，策略负责修正，δ 是设定值（set-point）**。这是本课程第四次出现这个架构。*

图上两处标注：

- **`speed rises → balls rise → sleeve lifts → throttle closes`**
  （转速升高 → 飞球张开 → 套筒抬起 → 节流阀关小）—— 一条完整的负反馈链，**没有任何一步需要人**
- **`no measurement without consequence; no consequence without measurement`**
  **没有不产生后果的测量；没有不基于测量的后果**

| | 闸门（gate） | 调速器（governor） |
| --- | --- | --- |
| 是什么 | 一个固定的 τ | 一个反馈回路 |
| 谁在调 | 人，手动 | **系统自己，持续** |
| 你设定的是 | 阀门开度 | **目标转速（δ）** |

**你不再设定"阈值是多少"，你设定"我要的错误率是多少"，系统自己找阈值。**

### ⭐ 那句标注是闭环控制的完整定义

> **"no measurement without consequence; no consequence without measurement"**

两个方向各堵死一种失败：

| 违反 | 症状 | 在缓存里长什么样 |
| --- | --- | --- |
| **有测量、无后果** | 监控变摆设 | 跑了探索、拿到标签，**却没有回去更新曲线**——花了钱买知识，然后扔了 |
| **有后果、无测量** | 拍脑袋 | **凭感觉把 τ 从 0.92 调到 0.90**，没有任何数据支撑，也没有回看结果 |

**第二种是绝大多数团队的现状。**p.27 那张图之所以每条支路最后都回到 `update entry i's curve`，就是在保证第一条。

映射关系：

```text
调速器             误差合同
──────────────────────────────
飞球（测转速）  →  exploration（测错误率）
套筒（传动）    →  per-entry 曲线更新
节流阀（执行）  →  serve / explore / near-miss 的分流
设定转速        →  δ
```

> 讲义说这是本课程**第四次**出现这个架构——值得回头找找前三次分别在哪（Week 06 的两道门？Week 07/08 的裁判？Week 09 的 OKF 过期巡逻？）。

## p.29 · 一次服务的经济学：VoS

$$\text{VoS} = p\,g \;-\; (1-p)\,L \;-\; \kappa \qquad\Longrightarrow\qquad \textbf{serve iff}\quad p > \frac{L+\kappa}{g+L}$$

| 符号 | 含义 |
| --- | --- |
| $p$ | 这次命中是对的概率 |
| $g$ | 答对省下的（gain） |
| $L$ | 答错的代价（loss） |
| $\kappa$ | **做这次查找本身的成本**（embedding + 向量检索 + 决策） |

> *一条定律，三扇门：**VoL** 给一次查找定价，**VoR** 给一次回忆定价，**VoS** 给一次服务定价。**缓存的标志性项是 $(1-p)L$ —— 那个被自信地送出去的陈旧答案。***
>
> *赌注定门槛：当**答错比答对好二十倍还糟**时，你在碰旋钮之前就需要 $p > 0.95$。*

验算：$L = 20g$、$\kappa = 0$ → $p > 20g/(g+20g) = 20/21 = 0.952$ ✓

### ⭐ 修正我们自己的推导

我们在 [`sigmoid-decision.zh.md`](sigmoid-decision.zh.md) 推的是

$$p^* = \frac{C}{G+C}$$

**那是 $\kappa = 0$ 的特例。**讲义多了 $\kappa$ —— **查找本身也要花钱**（要调 embedding、要查向量库）。所以真实门槛比我们算的**更高一点**：

$$p^* = \frac{L+\kappa}{g+L}$$

$\kappa$ 大到接近 $g$ 时，$p^*$ 趋近 1 —— **意思是：如果查缓存本身就跟重算差不多贵，那就根本不该有这个缓存。**这也从另一个角度解释了 p.6 为什么要在语义层前面放一个免费的精确哈希层。

### $(1-p)L$ 是缓存独有的项

VoL（查找）和 VoR（回忆）失败时，最多是**白花钱、没帮上忙**。
**缓存失败时是主动送出一个错答案。**

> **"the stale answer served with confidence"** —— 陈旧的答案，被自信地送出去。这一项是缓存区别于其他"该不该做"决策的地方，也是整门课反复警告的东西。

## p.31 · Quiz 2 答案：**一个都不选**

> # Quiz 2 — answered: none of them
>
> *在 0.90：**B 端出毒药**。在 0.97：**A 饿死**——而且 **B 仍然重叠**。在 0.93：**两种失败同时发生**。这些选项是个**陷阱**——**不存在这样一个标量**；解法是**逐条目的策略：误差合同**。*

| 选项 | 对 A（正确改写低至 0.83） | 对 B（错误匹配高至 0.96） |
| --- | --- | --- |
| **(a) 0.90** | 0.83–0.90 的正确改写全部落空，**缓存半死** | 0.90–0.96 的错误匹配照样服务，**端出毒药** ☠️ |
| **(b) 0.97** | **A 彻底饿死** | **仍然重叠** ⚠️ |
| **(c) 0.93** | 仍然饿着 | 0.93–0.96 仍然答错 ☠️ **两种失败同时发生** |

> ⚠️ **注意 (b) 那一栏**：直觉上 0.97 > 0.96 应该安全了，但讲义明确写 **"B still overlaps"**。因为 **0.96 是观测到的最大值，不是分布的硬上界**——尾巴还在往上延伸。**"把阈值设在观测最大值之上"是一种幻觉安全。**

**根本原因：两条条目的要求区间根本不相交。**

```text
A 需要：  τ ≤ 0.83  ├────────┤
B 需要：  τ > 0.96                        ├──────┤
                    └── 中间没有交集 ──────┘
```

> **这不是"没调好"，是"不存在"。**这道题是 p.22 那句 *"there isn't one"* 的构造性证明，也是 **per-entry 曲线为什么是必需品而不是优化项**的全部论证。

### ⭐ 右边那段才是真正的杀招

> *一个被迫从给定选项里挑一个的**学生**，就是一个被迫从给定上下文里作答的**模型**。**"以上皆非"就是负向拒答——把它一直上着膛。***

**这道题本身就是一次演示。**出题人故意只给三个错误选项，逼你选——**这正是 RAG 里 context 不包含答案时发生的事**：模型被上下文困住，只能从错的里面挑一个最像的，然后自信地说出来。

**幻觉不是模型在编造，是模型被迫作答。**

| | 学生 | 模型 |
| --- | --- | --- |
| 被给定 | 三个选项 | 检索到的 chunk |
| 被要求 | 必须选一个 | 必须回答 |
| 正确动作 | 说"以上皆非" | **负向拒答**（"资料中没有相关信息"） |
| 没有这个动作时 | 蒙一个 | **幻觉** |

**"keep it loaded"（一直上着膛）**——负向拒答不是异常路径，是**必须常驻的一等选项**。

> 这条直接串回 Week 06 的「两道门」和 [`rag-request-flow.zh.md`](rag-request-flow.zh.md) 里 system prompt 那句"资料中找不到答案时，明确说找不到"。**讲义在这里用一道题证明了那句 prompt 为什么不是可选项。**
>
> 而且它和缓存的三个出口是同构的：**serve / explore / near-miss 里的后两个，就是缓存版本的"以上皆非"。**
