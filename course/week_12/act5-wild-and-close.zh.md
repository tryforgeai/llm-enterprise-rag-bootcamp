## p.60–61 · Quiz 6：被移植的阈值

> 一个工程师把久经沙场的 `threshold: 0.2` 从 Kong 配置复制进 Portkey 部署，理由是"保持缓存行为一致"。

**答案：**

> *Kong 的 0.2 是**距离**（严格）；Portkey 的 0.2 是**相似度** —— **接近地板**。这个设置**不是把缓存放松了，是把它的含义倒转了**：**索引返回的几乎所有东西现在都会被送出去。***
>
> ***说回来：是相似度还是距离？哪个方向更严格？—— 检查旋钮的符号。而在这片混乱背后，ACT II 的判决依然成立：这些旋钮，每一个都只是阶梯的第一级。***

### 实际后果

Kong `distance ≤ 0.2` = 余弦 ≥ 0.8（严格）
Portkey `similarity ≥ 0.2` = **几乎无条件放行**

回想 p.14 的各向异性：**毫不相关的两句话余弦也有 0.7~0.85** → 门户大开。

**最阴险的部分：仪表盘看起来棒极了。**

```text
命中率：20% → 99%  📈     成本：↓95%  📉     p95 延迟：2s → 40ms  📉
```

**这正是 p.53 洗白的活体标本**——只报 hit rate 的团队会把这次事故当成本季度最大的工程胜利，直到客户投诉堆积。

### ⭐ 这是 "δ is portable and τ never was" 的生活版

| 搬运的东西 | 搬过去还成立吗 |
| --- | --- |
| `threshold: 0.2` | ❌ **方向反了，尺度也变了** |
| **"错误率 ≤ 2%"（δ）** | ✅ **依然成立** |

> 前面讲 τ 不可移植时举的例子都是"换 embedding 模型"——听起来像偶尔才发生的大动作。**这道题说：连换个网关都不行，一次复制粘贴就够了。**

### 建议的配置写法

```yaml
# ❌ threshold: 0.2

# ✅
similarity_threshold: 0.80        # 方向写进字段名
  # metric: cosine_similarity (higher = stricter)
  # calibrated_on: bge-large-zh-v1.5, index hnsw-2026-08-01
  # target: Pr[wrong serve] <= 0.02, demonstrated 1.7%
  # DO NOT COPY to another encoder or gateway — recalibrate
```

**把 δ（目标）和标定条件写在 τ（数值）旁边**，让下一个人复制粘贴时至少能看见警告。

## p.62–63 · THE PATTERN LANGUAGE：十个模式

| 模式 | 一句话 | 出处 |
| --- | --- | --- |
| **Front Door** | 精确 → 语义 → 流水线，**回写** | 序幕 |
| **Canonical Key** | **缓存意义，不是措辞** | 序幕、ACT III |
| **Two-Tier Threshold** | **上面服务，下面提示**（serve above, hint below） | 课上讲的 |
| **Error Contract** | 预算 δ，逐条目曲线 | ACT II |
| **Verified Hit** | 裁判把证据转成担保 | ACT II |
| **Scoped Cache** | **范围键在键里面** | Interlude |
| **Version Pin** | **条目随它的几何一起死** | ACT III |
| **Evidence Gauntlet** | **新鲜度对抗世界，不是对抗时钟** | ACT III |
| **Plan Cache** | **复用工作的形状** | ACT III |
| **Near-Miss Mine** | **那条带就是训练数据** | ACT III |

> 📌 **Two-Tier Threshold（"上面服务，下面提示"）** 是唯一只在课上讲、讲义没展开的一条：高于上阈值直接服务，落在中间带则**不直接给答案，而是把缓存内容当成"提示/候选"喂进流水线**——既不冒险，也不浪费。

## p.64 · THE ANTI-PATTERNS ⭐

> ***每一个反模式，都是一次「有操作、无策略」。***

| 反模式 | 是什么操作 | 缺了什么策略 |
| --- | --- | --- |
| **Global Threshold**（全局阈值） | 一次 **serve** 操作 | **决策策略**（decision policy） |
| **Unscoped Shared Cache**（无范围共享） | 一次 **share** 操作 | **访问策略**（access policy） |
| **Hit-Rate Worship**（命中率崇拜） | 一次 **measurement** 操作 | **真相策略**（truth policy） |
| **Checkbox Cache**（打勾式缓存） | 一次 **deployment** 操作 | **归属策略**（ownership policy） |

> ***命中率是那个危险的指标：**当答案变得更糟时，**它会上升**。**盯住误差，否则命中率会盯上你。***

**这个"操作 / 策略"的框架非常好用**——它把四个看似无关的错误统一成同一个形状：**你执行了一个动作，却没有一条规定这个动作何时正当的规则。**

- **Checkbox Cache**（打勾式缓存）是最容易被忽略的一条：**上线了，但没人负责**。没有 owner 就没有人重算 $H^*$、没有人看 false hit rate、没有人在 embedder 升级时钉版本。

## p.65–66 · SAY IT BACK：五件仪器 ↔ 五种失败

> 五件仪器：**极冠界** · **误差合同 δ** · **证据夹道** · **范围键** · **盈亏平衡 $H^*$**
> 五种失败（打乱）：**烧钱坑** · **偶然命中** · **陈旧服务** · **租户泄露** · **自信的错答案**

**揭晓：**

| 仪器 | 抓住的失败 | 备注 |
| --- | --- | --- |
| **cap bound**（极冠界） | **偶然命中** | 讲义特意加了一句：**根本不存在偶然命中——命中都是有因的** |
| **error contract δ** | **自信的错答案** | |
| **evidence gauntlet** | **陈旧服务** | |
| **scoped key** | **租户泄露** | |
| **break-even $H^*$** | **烧钱坑** | |

> ***几何让这个赌注成为可能；策略让它诚实；范围让它安全；算术决定到底要不要下注。***

**一件仪器缺席 = 一整类失败没人管。**这张对照表可以直接当自查清单。

## p.67–69 · PROMISES KEPT · WHY / WHAT

### The WHY（p.68）

> *真实流量中的重复是**头部集中的、且是近似的**；模型会用一千种措辞回答同一个问题一千次。**语义缓存是整个架构里唯一一个——它的成功要用「从未发生的前向传播」来衡量的器官。***
>
> ***缓存是一场"过去会重演"的赌注。而手艺，在于知道——逐条目、逐用户、逐时刻——这个注什么时候可以安全地下。***

**`head-heavy and approximate` 两个词就是全部理由，各自否决一种替代方案：**

| 性质 | 如果没有 |
| --- | --- |
| head-heavy | 命中率太低 → **不值得建** |
| approximate | **prefix caching 就够了** → 不必建 |

**"成功以从未发生的前向传播来衡量"的后果：**

- **没做的事不产生日志** → 它的价值天然不可见、难归因、**最容易在预算评审里被砍**
- **它越成功，系统看起来越像不需要它**
- 所以它必须有**专门的仪表盘**——它不像别的组件那样能自证

**三个 "per" 正好是三幕**：per entry → ACT II（δ 曲线）；per user → Interlude（scoping）；per moment → ACT III（证据夹道）。

### The WHAT（p.69）：五件仪器 = 五个粒度

| # | 仪器 | 回答 | 粒度 |
| --- | --- | --- | --- |
| 1 | cap bound | 这次命中是偶然吗？ | **一次命中** |
| 2 | error contract δ | 我承诺什么？ | **一条条目** |
| 3 | VoS / $p^*$ | 这次该不该返回？ | **一次服务** |
| 4 | evidence gauntlet | 这条答案还新鲜吗？ | **一条答案 × 时间** |
| 5 | $H^*$ | 系统该不该存在？ | **整个系统** |

## p.70 · The HOW ⭐ 周一早上的清单

> *周一早上，**按顺序**：
> ① 打开 **prefix caching**（**免费、无风险、约 60% 的收益**）；
> ② 跑**可行性闸门**（**抽样查询中十分之一能在 0.85 匹配上 —— 否则不要建**）；
> ③ 只在**密集、已划范围的切片**上部署那把**手术刀**；
> ④ **签下误差合同**；
> ⑤ **每周**给样本打分。*
>
> ***prefix caching 是默认项。语义缓存是一把手术刀 —— 而决定它往哪儿切的是那张表格，不是热情。***

### 逐条

| 步 | 动作 | 为什么排这个位置 |
| --- | --- | --- |
| **①** | 开 prefix caching | **免费、零风险、拿走 ~60% 收益**。不先做这步，后面所有 $g$ 的估算都是虚高的 |
| **②** | **可行性闸门** | ⭐ 见下 |
| **③** | 手术刀只切**密集 + 已划范围**的切片 | 密集 → $N$ 大、$H$ 高；已划范围 → Interlude 的安全前提**先于**部署 |
| **④** | 签误差合同 | 上线前就把 δ 定死，而不是上线后再说 |
| **⑤** | 每周打分 | 调速器的反馈环：**没有不产生后果的测量** |

### ⭐ 第 ② 步是全篇最实用的一句

> **"one in ten sampled queries matching at 0.85 — or do not build"**
> **抽样查询里有十分之一能在 0.85 匹配上 —— 否则别建。**

**这是 $d'$ 和 $H^*$ 的廉价代理测试**：不需要建任何东西，一个下午就能跑完。

```python
# 从真实 query log 抽 1000 条
sims = [max_cosine_against_others(q) for q in sample(query_log, 1000)]
frac = mean(s >= 0.85 for s in sims)
print(f"{frac:.1%} —— 低于 10% 就别建")
```

**它同时检验了 p.68 说的两个必要条件**：够不够 head-heavy（有 1/10 能匹配上），以及重复是不是 approximate 的（0.85 而不是 1.0）。

> **"the spreadsheet, not the enthusiasm, decides where it cuts"**（决定往哪儿切的是表格，不是热情）—— 呼应 p.52 的「别建是分析的成功」。
