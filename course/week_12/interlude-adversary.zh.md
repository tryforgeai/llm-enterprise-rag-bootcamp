## p.41 · "the theorem, weaponized" 是什么意思

ACT I 的整个防御建立在这条不等式上：

$$\Pr[\text{随机向量落入极冠}] \le e^{-d\varepsilon^2/2} \approx 2\times10^{-7}$$

**注意「随机」两个字。**这条定理的前提是**均匀随机采样**。

**而攻击者不采样，他优化。**

```text
随机撞进极冠：  千万分之二      ← 定理保证的
优化着走进去：  基本必然成功     ← 定理什么都没说
```

> **定理没有被推翻，是它的前提被绕开了。**同一个几何事实，换一个使用者，**从盾牌变成地图**。

## p.42 · THE BEAR SUIT：位置可以被购买

> # Placement can be purchased
>
> *几何认证的是**位置**，从不认证**意图**。在 token 上做**梯度搜索**，就能造出一段**披着高于 τ 的余弦**的 prompt —— **抵达极冠只证明了「有东西把你放在了那里」。***

### 图的读法

```text
                    ● victim query（受害者查询 = 北极点）
          ●    ★         ●          ← legitimate bears：合法邻居
  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─      cos θ = τ（冰线）
        ↗
   adversary:                    the bear suit：
   gradient search               一段**语义上毫不相关**的 prompt，
   over tokens                   被梯度**裁剪**进极冠
```

**注意 ★ 的位置**：它**紧贴冰线上方**，不在北极点附近。

> **攻击者只需要刚好越过 τ，不需要爬到极点。**越省事越好——这是经济学，不是炫技。

### 标题的妙处

回想 **p.13**：极冠里的熊是"被训练放进去的"。

**现在：攻击者可以穿一件熊皮衣。**几何分不出真熊和穿熊皮衣的人——它只能测量"你站在哪里"，测不出"你为什么站在这里"。

### ⭐ `The geometry authenticates placement, never intent`

**这是整个 Interlude 的中心句。**

| 几何能回答 | 几何不能回答 |
| --- | --- |
| 这个向量在极冠里吗？ | 它**为什么**在这里？ |
| 它离 query 多近？ | 放它进来的人**想干什么**？ |

- **p.13 说"每次命中都是有因之事"** —— 好消息，排除了偶然
- **p.42 说"但几何看不出是哪种因"** —— 坏消息，**"有意的"和"善意的"长得一模一样**

### `Gradient search over tokens`

**把 token 序列当成优化变量**，目标函数是"与目标缓存条目的余弦相似度"，然后梯度上升：

```text
初始：随机一段文本                cos = 0.02
迭代 100 次，每次替换几个 token    cos = 0.61
迭代 1000 次                      cos = 0.94   ← 越过 τ
```

产出的文本**对人来说可能像乱码或看似无关的句子**，但在 embedding 空间里它**就住在你的极冠里**。图上写得很直白：*a prompt **semantically unrelated**, gradient-tailored into the cap*。

> 这和对抗样本、GCG 类越狱攻击是同一个技术家族。**embedding 空间的连续性既让语义检索成为可能，也让梯度攻击成为可能。**

### `arrival proves only that something put you there`

这句是 p.13 的**精确削弱版**：

| | p.13（ACT I） | p.42（Interlude） |
| --- | --- | --- |
| 说的 | 每次命中都是**有因之事** | 抵达**只**证明**有东西**把你放在那儿 |
| 语气 | 这是保证 | 这**仅仅**是保证 |
| 潜台词 | 排除了偶然 ✅ | **但没排除恶意** ⚠️ |

**"something"（某个东西）这个模糊词是故意选的**——可能是训练，可能是真同义，也可能是一个跑了一千次梯度下降的人。

## p.43 · THE THEOREM, INVERTED：定理被倒转

> # Locality ⇄ collision
>
> *让命中具有因果性的**那个**集中性，也让**精心构造的碰撞变得便宜且好瞄**：攻击者只需要抵达**一个小小的极冠**，而**那个极冠恰恰就是你全部合法流量所在的地方**。**对抗性 hubness** 只要种下**一个**条目，就能回答**很多**查询。*
>
> ***缓存之所以能工作的每一个性质，都是它的攻击面。不存在一种既开放又安全的配置。***

### 「小极冠」的双重性

| 对谁 | 极冠小意味着 |
| --- | --- |
| **随机文本** | 几乎不可能撞进去 → **这是墙** |
| **优化器** | 一个明确、集中、**高价值**的目标 → **这是靶心** |

**同一个几何性质，对两种使用者意义完全相反。**

而且极冠不只是"小"，它还是**你全部合法流量所在的位置**——攻击者不需要找目标，你的流量分布已经替他标好了。

### 对抗性 hubness = 人造 hub

**这证实了我们在 p.18 的猜测**：*"一个条目劫持大量 query"* 正是 hub 的定义，只不过这次是**人造的**。

```text
攻击者构造一条对海量不相关 query 都有高相似度的条目
   ↓ 一次投毒
   ↓
「怎么报销？」「年假几天？」「Q3 营收？」…… 全部命中它
   ↓
长期、大面积地劫持答案
```

> **防御沿用 p.18 的处方**：入度分布监控（人造 hub 的入度必然异常）+ CSLS（人造 hub 的 $r_k$ 必然异常高，会被局部缩放压下去）。**入度监控 = 便宜的投毒探测器。**

### ⭐ 那句判决

> ***Every property that makes the cache work is the attack surface. There is no configuration that is both open and safe.***

**这不是"要小心配置"，是"不存在安全配置"。**逐条对应：

| 让缓存能工作的性质 | 同时也是 |
| --- | --- |
| 近似匹配（不必一字不差） | 攻击者不必猜中原文 |
| 跨用户共享（收益来源） | 一次投毒污染所有人 |
| 集中性（随机进不来） | 靶心明确、命中率高 |
| 高命中率的头部流量 | **高价值目标已被你标好** |

**收益和风险不是两件事，是同一件事的两面。**这也解释了为什么这一幕叫 Interlude 而不是 ACT——它不推进方案，它是在两幕之间**收走你的乐观**。

## p.44 · THE DEFENSE AND ITS PRICE：划范围、验证，两样都付钱

> ***永远按租户划范围**，内容个性化的地方**按用户划**——**范围键住在缓存键里面，而不是在应用层的一个检查里**。划范围会**腰斩可共享的人群**；验证会**对每一次受保护的命中征税**。**$H$ 要在防御之后再报，不是之前。***
>
> （$H$ = hit rate，命中率。讲义用的是这个符号。）

### 五种防御，各自的收益与代价

| 防御 | 买到什么 | 代价 |
| --- | --- | --- |
| **key salting** 键加盐 | 抬高攻击者的搜索成本 | **打乱诚实的邻域** |
| **perplexity screen** 困惑度筛查 | 拒掉乱码做的熊皮衣 | **是棘轮，不是墙** |
| **centroid matching** 质心匹配 | 不再有"单点最近邻" | **匹配变粗** |
| **verification** 验证 | 抓住已经端出去的胡话 | 延迟 + 裁判成本 |
| ⭐ **scoping** 划范围 | **直接移除靶子** | **命中率**（可共享人群变小） |

逐条说明：

1. **key salting** —— 给缓存键加一个秘密扰动（按租户/按周期）。攻击者不知道盐，**无法离线精确瞄准**——他优化出的向量落在别处。代价：**盐同样会打乱真实的改写**，诚实邻居也可能对不上。

2. **perplexity screen** —— 用语言模型算候选文本的困惑度，梯度搜索产出的对抗文本通常像乱码，困惑度极高，直接拒。
   > **"ratchet, not a wall"（棘轮，不是墙）**——这个说法很精妙：它只是把门槛往上**抬一格**。攻击者在优化目标里加一项"保持流畅性"重新跑，就绕过去了。**它能推进军备竞赛，不能终结它。**

3. **centroid matching** —— 不用单个最近点判命中，要求 query 靠近一个**簇的质心**、或需要多个点共同支持。攻击者种**一个**点没用，得种**一片**。代价：匹配粒度变粗，细分辨别能力下降。

4. **verification** —— 就是 p.27 那套裁判。它不阻止攻击进入，**只阻止胡话出门**。

5. **scoping** —— 讲义把它**高亮框了出来**，是首选。

### ⭐ 为什么 scoping 被单独框出来

**前四个改变的是「打靶有多难」，只有 scoping 改变的是「有没有靶子」。**

```text
key salting / perplexity / centroid / verification
   → 攻击者仍然有一个明确目标，只是更贵、更容易被抓
scoping
   → 攻击者根本够不到你租户的缓存空间：没有靶心可瞄
```

这和 Quiz 4 的 **"结构胜过警惕"** 是同一条原则：**能让攻击"无从下手"时，就不要只让它"更难得手"。**

### ⭐ 所有代价都用缓存自己的价值支付

把"代价"那一列竖着读，会发现一件事：

| 防御牺牲的 | 而这恰恰是 |
| --- | --- |
| 诚实的邻域（salting） | 语义缓存的**立身之本** |
| 匹配精度（centroid） | 它区分对错的能力 |
| 可共享人群（scoping） | 它**全部收益的来源** |
| 延迟（verification） | 它**存在的理由之一** |

**你只能通过削弱缓存本身来保护缓存。**

> 这就是 p.43 那句 *"Every property that makes the cache work is the attack surface"* 的操作版本——**不是一句警句，是一张账单。**

---

底下那段话的三个要点：

### ① 范围键必须在 key 里面

```python
# ❌ 应用层检查
entry = cache.lookup(embedding)
if entry.tenant_id != user.tenant_id:      # 一个 if 语句
    entry = None

# ✅ 范围键进 key
key = hash(tenant_id, acl_group) + embedding
entry = cache.lookup(key)                  # 根本查不到别人的
```

理由见 p.46。

### ② 划范围**腰斩**收益

**这是必须正视的代价。**缓存的价值来自共享——按租户切开，可共享人群就小一个数量级：

```text
全局共享：  10000 个用户共享一条「报销流程」→ 命中率高
按租户切：  每个租户各自 100 人 → 每条条目要被独立地"学"一遍
按用户切：  共享人数 = 1 → 语义缓存基本退化成个人历史
```

**个性化程度越高，缓存的经济性越差。**这是结构性的，不是实现问题。

### ③ **$H$（命中率）要在防御之后再报**

> ***Quote $H$ after the defense, not before.***

**这句是给做方案的人的直接警告。**

先算出"命中率 60%、能省 90%"再去加隔离和验证，数字会缩水到面目全非：

```text
裸算：              H = 60%，省 90%
加租户隔离：         可共享人群腰斩   → H ≈ 30%
加验证层：           每次守卫命中征税 → 净省 ≈ 30%
加探索成本 κ：                       → 净省 ≈ 20%
```

**拿裸算的 $H$ 去承诺，等于给自己挖坑。**而且这个坑是不可逆的——防御不能事后砍掉。

## p.45–46 · POP QUIZ 4：邻居租户

> **题**：两个客户共享你的语义缓存。租户 A 的分析师问「我们 Q3 营收是多少？」，答案被缓存。第二天早上租户 B 的分析师问**一模一样的话**。
>
> 判一判：缓存键必须满足什么条件，这件事才是安全的？
> 然后**说回来**：为什么在应用代码里写一个 `if tenant_id != ...` 的检查**不是**一个可接受的答案？

### 答案

> ***租户 ID 必须住在键里面**——同样的措辞、不同的租户，**在结构上就是不同的键空间**：**这次查找根本找不到那条外来的条目，所以没有东西可泄露。***
>
> **说回来**：*一个检查**禁止**了泄露；一个带范围的键让泄露**不可能发生**——而 MemoryCraft 的分区插曲早就说过了：**结构胜过警惕，因为警惕会宕机。***

### 为什么 `if` 不够

| | 应用层检查 | 范围键 |
| --- | --- | --- |
| 泄露的可能性 | **存在**，被一行代码挡着 | **不存在**，查不到就是查不到 |
| 失效方式 | 有人重构时删掉；新加的一条调用路径忘了加；异常分支绕过 | 无 |
| 属于 | **警惕**（vigilance） | **结构**（structure） |

> ***结构胜过警惕，因为警惕会宕机。***
>
> **这条是可以直接搬进任何安全设计的原则**，不限于缓存：**能让错误"不可能发生"的时候，就不要让它"被禁止发生"。**

（这也回指 Week 10 的 MemoryCraft —— 讲义说"分区插曲早就说过了"，可作为补 Week 10 记录缺口的又一条线索。）
