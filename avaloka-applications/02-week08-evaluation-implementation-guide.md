用途：把今天一整天的评估课，转成 Avaloka AI 可以**立刻照做**的、按优先级排序的实施清单。每一项标了 **必须/应该/以后**，并说明**为什么**、**检测点（哪个数 + 阈值）**、**具体步骤**。

## 0. 一句话定调（为什么现在就要做）

课程铁律：**你无法改进你无法测量的东西；约 70% 的 RAG 系统没有系统化评估；评估不是下游验收，评估就是 AI 工程本身。** Avaloka 处理的是**个人记忆**——一个「事实正确但无据」或「没证据也硬编」的回答，是**最危险的失败**。所以 Avaloka 的安全卖点（温暖但不越界、诚实的「我不知道」）**不测量就只是希望**。这份指南让 Avaloka 站到会做系统化评估的 30% 一边。

优先级定义：
- **P0 必须**（上线前 / 本周就做）：不做，你就在那 70% 里，且任何架构升级都是赌博。
- **P1 应该**（紧接着）：生产硬化。
- **P2 以后**：进阶 / agentic / 上线后运维。

## P0 · 必须（本周的最小闭环）

### P0-1 金 EVAL 集（尺子）——一切的地基
**为什么必须**：Act I 第一诫「尺子得你自己造」。**没有 ground truth,下面每个指标都算不出来、都没意义**。这是 80% 的精力所在,也是「证据驱动架构升级」决策（`decisions/2026-06-06-evidence-driven-architecture-escalation.md`）的前提——没有基线,你无法证明 RAPTOR/GraphRAG 有用。

**具体步骤（cherry-pick 五步法）**：
1. **SME = 你本人 + Care Card 真实意图**（从真实使用日志/工单出题,不要工程师凭空编）。
2. 每个 query,用现有简单引擎捞 **top 100–200 候选**（可扫,不是百万级）。
3. SME 精挑并按 **0–4 分级相关性**打分最佳 25–30 条（0 无关…4 完美）。
4. **冻结 + 版本化**（`evals/gold/carecard-v1.jsonl`）,每次发版随语料演进。
5. 规模：**SME Summit 先冲 100 条**分级 query → 最少 200 → 目标 1000。

**检测点**：集合大小 N（≥200 起步,功效分析：检测 1 分 nDCG 提升需 N≈500–1000）；真实意图覆盖度。

---

### P0-2 检索指标基线（阶梯）——Memory Reader V0 的体检
**为什么必须**：这就是你已定的 benchmark 决策（`decisions/2026-06-06-benchmark-memory-reader-before-upgrade.md`）。**升级架构前必须有基线**,否则「变好了」只是错觉（Act II「相关性陷阱」：检索指标涨 ≠ 答案变好,但没有它连涨没涨都不知道）。

**具体步骤**：
1. 用 `pytrec_eval` / scikit-learn 在金集上算 **Recall@5、MRR、nDCG@5**。
2. 注意 **gain 约定**：`2^rel−1`（scikit-learn/pytrec_eval 默认）——跨约定的 nDCG 不可比。
3. 每个分数旁边**打印 judged@k**（判过多少,防 qrels 的洞）。

**检测点 + 诊断对**：**nDCG@5 配 Recall@5**——
- nDCG 低、Recall 高 → 文档找到了但排序差 → **修 reranker**
- 两者都低 → 没找到 → **修检索**（chunking/embedding/hybrid）
- 都高 → 进生成侧

---

### P0-3 两道门的测量（faithfulness + 负拒绝）——把上周的机制证明为真
**为什么必须**：「机制没有测量只是希望;没有它,guardrail 只是装饰。」上周（W6）你造了两道门(机制),但**你不知道它在该触发时真的触发了没有**。对个人记忆助手,**参数泄漏/幻觉是最危险的单一失败**（Calabi–Yau 测试:RGB 实测 ChatGPT 级负拒绝仅 43–45%,即多数时候没证据也编）。

**具体步骤**：
1. **Faithfulness**：把答案拆成声明,每条对检索证据做 **NLI 蕴含核验**（复用 W6 的断言-证据二部图 + DeBERTa 后端,你在这项通常得分高——但仍用外部尺子测）。
2. **负拒绝率 NRR**：造一个 **Avaloka 不可答测试集**（域外:天文/法律/八卦 + Care Card 里根本没有的私事）,测**诚实弃权比例**。用 **Calabi–Yau 探针**（问明显语料外的东西看它认不认怂）。
3. **成对报告**：NRR（不可答上的拒绝率）+ **过度拒绝率**（可答上的误拒率）——单看任一个都能被作弊。

**检测点**：faithfulness %（越高越好,配外部 judge）；**NRR 向监管门槛 >70% 靠拢**,同时过度拒绝率低。

---

### P0-4 一个被校准的评委（不同家族 + κ 门）——先校准显微镜
**为什么必须**：你要用评委在规模上给 faithfulness/质量打分,而**评委本身是台有人差方程的仪器**（Personal Equation 实验 1:显微镜自己也要校准）。**Quiz 11 的坑**:用生成 Avaloka 答案的同一个模型当评委 → 自我陶醉、分数虚涨、质量原地踏步。**评委不校准,整个仪表盘都是噪声。**

**具体步骤**：
1. 用**本地专用评委**（Prometheus 2 级）,**和 Avaloka 生成模型不同家族**（防 self-enhancement/合谋）。
2. **钉到带日期的 checkpoint**（防厂商偷偷更新）。
3. 维护一个**冻结的 50–200 条人工标注校准集**（你自己标）,算 **Cohen's κ**;**κ<0.6 一律拒用**;定期重跑,**κ 漂移 >0.05 报警**。
4. 评委三铁律：不同家族 · 成对比较两个顺序都平均 · 永不信单一评委（必要时上 PoLL 三评委陪审团）。

**检测点**：**Cohen's κ ≥ 0.6**（对外报的绝对数字必须来自达标评委）。

---

### P0-5 离线闸门（CI 卡合并）——让指标真正保护产品
**为什么必须**：「eval 套件在它能卡住一次合并的那天,才成为基础设施。」否则上面四项只是好看的仪表盘,不是护栏。这一步把评估从「报告」变成「守门人」——**「你不会在那 70% 里」的字面兑现**。

**具体步骤**：
1. 把「金集回归（Recall/nDCG）+ faithfulness + NRR」接进 **CI**,不达阈值就**阻止部署**。
2. 信任任何改进前先跑 **配对 bootstrap 显著性检验**（区间不含 0 才算真）。
3. 再过**实用阈值**：nDCG 改进 **≥0.02–0.05** 才值得上线（否则统计显著但没人感觉到）。
4. **棘轮**：每次生产失败 → 变成一个**永久、带版本的回归用例**,闸门此后永远拒绝它。

**检测点**：每次改动的 gate pass/fail;显著性区间;实用阈值。

## P1 · 应该（紧接着的生产硬化）

### P1-1 ECE（置信度诚实度）
**为什么是 P1 不是 P0**：需要 Avaloka 先**输出置信度**。分工:NRR 问「该弃权时弃权了吗」,**ECE 问「作答时它说的把握诚不诚实」**。「错的置信度比没有更糟」——用户会照 95% 行动。
**步骤**：让 Avaloka 输出置信度 → 在金集上分桶算 ECE → 高置信桶过度自信就上**温度缩放**（最便宜、不改答案对错,只压平自信）→ 画可靠性图。
**检测点**：**ECE < 0.05–0.10**;可靠性图柱子贴对角线（不塌下方）。

### P1-2 声明级 FActScore + 引用（ALCE）
**为什么 P1**：P0 的 faithfulness 是「地板」;声明级抓的是**粗判漏掉的腐烂**（Quiz 8:5 条原子事实 3 条支持 = 0.60,而语句级会虚高）。
**步骤**：答案 → 原子事实逐条核验（复用断言-证据图 + FActScore 数值）；**若 Avaloka 给用户展示来源,引用准确率设成部署硬门**——撑不住的脚注比没脚注更糟。
**检测点**：FActScore %；引用准确率（展示来源时）。

### P1-3 漂移探针（domain-classifier bet）
**为什么 P1**：上线数周/数月后才需要,但**必须在你长期信任它之前**上。RAG 会**悄悄退化**（生成仍流畅而检索挨饿,RAG 任务数月漂移 25–75%）。
**步骤（搭建配方）**：① 冻结 1000–5000 条上线时 query embedding（class0,不动）；② 每周抽等量实时 query（class1）；③ 训个简单分类器（逻辑回归/GBDT）分二者;④ 读 **AUC——≈0.5 睡得香,>0.65 报警**；⑤ 报警后:看哪些 query 最像 class1（新主题）→ 在漂移切片重测 Recall/nDCG → 刷新金集/重建索引。要点:两类样本量对齐、同一 embedding 模型、参考冻结较久。
**检测点**：AUC（报警阈值 ~0.65）。

### P1-4 每正确答案成本 + 小验证器路由
**为什么 P1**：规模化后的经济学。
**步骤**：追踪 **dollars/tokens-per-correct-answer**（`成本/成功率`,买的是正确答案不是查询,先除再比）；路由:**小验证器（MiniCheck/HHEM 级）逐条测每个回答 → RAGChecker 抽样 → 前沿 judge 只测没覆盖的维度**（拖鞋/好鞋）。
**检测点**：$/correct-answer;是否在 cost-quality Pareto 前沿上。

## P2 · 以后（进阶 / agentic / 上线后）

- **多轮评估（MTRAG 式）**：Care Card 本质多轮,所以优先级偏高——但等单轮稳了再上。测 contextual faithfulness（跨轮自洽）、context-switch（切话题重检索 vs 死抱旧上下文）、turn efficiency。用 LLM 模拟用户,但人工抽查防模拟器幻觉。
- **agentic / 轨迹评估**：当 Avaloka 变成 agent 循环时。三层:Level 1 效率 / Level 2 会话结果 / Level 3 **节点级（诊断力在此）**；**pass^k 进 SLA**（不是 pass@k——面向用户看「连续 k 个客户全成」）。
- **Goodhart 防护套装**：指标集成（永不优化单个数字）+ 对抗 eval + 红队攻击指标 + **从不用于训练的 held-out 金评委**（测漂移）。
- **conformal abstention**：需要 SLA 级、带分布无关保证的弃权时。
- **上线对比**：shadow / canary / interleaving（有真实流量体量后;interleaving 用 10–100× 更少流量选出用户偏好）。

## 本周可执行的构建顺序（照抄）

1. **金集**：SME summit,100 条分级 Care Card query,冻结 `evals/gold/carecard-v1.jsonl`。
2. **检索基线**：pytrec_eval → Recall@5 / nDCG@5,跑在 Memory Reader V0 上。
3. **两道门测量**：faithfulness（复用 W6 断言-证据图）+ NRR 测试集（不可答 + Calabi–Yau）,**成对报**。
4. **评委**：本地 + 不同家族 + 50–100 人工标注上 κ≥0.6 + 钉版本。
5. **离线闸门**：把 1–4 接成一个 pass/fail 检查,阻止不达标部署。

做完这五步,Avaloka 就有了「可测量、可诊断、可守门」的评估闭环——从 RAG **practitioner** 跨到 RAG **engineer**。

## 唯一最重要的一条（以及为什么）

**最深的指标不是 faithfulness、不是 nDCG,而是:Avaloka 知道自己何时不知道吗?**
一个 95% faithfulness、却从不说「我不知道」的 Avaloka,在它唯一答不了的那个 Care Card 问题上——会**撒谎**。对一个个人记忆助手,那个谎就是**丢掉用户信任**的失败。所以 **NRR + 诚实的「可信朋友」行为(有据的照答、无据的说「我们一起查」、先验标成「通常认为」)是不可妥协的核心**。最危险的从来不是它不知道,而是**它不知道却仍表现得非常确定**。

> 落到回应契约:据实回答(负拒绝)+ 把先验明确标为先验——就是 Personal Equation 实验 4 的满分答案形态:「资料里没有——不过通常认为是 X」。
